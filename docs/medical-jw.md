# 医学院教务课表

v0.7.6 迁入医学院教务的本地口令登录协议和当前学期课表解析，作为试验能力发布。实现及合成测试完成不代表真实账号已验收；本次没有使用医学院账号登录或向学校提交认证。

## 使用

在 MCP 宿主运行 `stu-mcp setup`，选择「医学院教务」，本人输入教务本地口令并填写学校图片验证码。也可在真实交互终端运行：

```sh
stu-mcp login med_jw
stu-mcp timetable --source med_jw
stu-mcp logout med_jw
```

MCP 工具为 `get_medical_timetable`，无参数。工具不接收账号、口令、验证码或令牌。医学院教务本地口令可能与医学院统一认证密码不同；本版未接入 `sso.med.stu.edu.cn` 的 CAS 登录。主校区 `login school` 和 `get_academic_timetable` 继续使用原有来源。

## 范围与结果

- 仅按需读取 `Studentkb/index` 返回的本人当前学期课表，不提供成绩、考试、历史学期选择、选课、签到或后台同步。
- 保留学校原生学期、周次与日期信息，不把主校区校历或调用方传入的学期贴到响应上。`--semester` 对医学院返回明确的不支持状态。
- 课程与安排采用现有课表领域字段；地点、教学班和明确时间差异保持区分，标识跨进程稳定。
- 缺少 `kbList`、无效 JSON 或顶层类型错误返回结构错误。个别坏行保留其余可识别课程，同时返回 `pending` 和 `coverage.complete=false`；显式有效空列表可表示空课表。
- 结果不写入课程缓存、手动课表或个人日程。日期导出前仍须核对医学院校历、作息和调课，不能以周次自行推算开学日。

## 共同架构

协议常量与响应契约位于 `features/med_jw/schema.py`，纯课表解析位于 `parser.py`，固定只读请求位于 `adapter.py`，按需读取和会话代次保护位于 `service.py`。`auth_http/med_jw.py` 复用有界直连 HTTP 和私有交互；CLI、设置页、MCP 共用现有编排。

会话为独立 `med_jw` Vault 条目，仅保存加密业务令牌，不复制主校区或医学院 SSO Cookie，不保存普通口令。认证要求成功状态、匹配输入账号的学生身份和新令牌可读课表证明；仅有 token 不算成功。认证与业务请求只访问固定 HTTPS 主机和路径，不跟随重定向携带令牌，不重试结果未知的口令提交。注销、取消和换账号的保存保护沿用共同核心，读取完成前再次核对会话代次。

APP 的多租户表、FastAPI 路由、定时采集、界面及密码持久化均未迁入；也没有修改 APP 对这些能力的调用。本版发布后，可由 APP 的适配层调用这里的公开服务，后续删除其重复实现。

## 依据和验证边界

协议与样本结构参考 `csensicrigley-netizen/stu-assistant` 的 `a8d2023504c7bb47228fb52270418a3805726aec`。其中接口文档的静态拆包、匿名访问与已登录课表结构注释是不同证据；未将这些记录当作本项目新版真实认证成功。来源及 MIT 声明见 [provenance.json](provenance.json) 和随包 `features/med_jw/NOTICE.txt`。

自动化测试使用合成账号、模拟 HTTP 响应、临时 Vault 与数据库，覆盖解析完整性、身份不符、人工验证码、401、响应预算、重定向、取消与注销竞态。实际学校首登、当前字段兼容性和医学院网络条件仍需符合该系统身份的用户验收。
