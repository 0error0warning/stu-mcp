# 学期课表与文件导出

v0.7.1增加 `get_academic_timetable` 和 `stu-mcp timetable`，读取教务本人理论课表。已有 `stu-timetable-export` 技能继续核对目标学期最新有效校历和作息，调用唯一转换核心生成 WakeUp CSV / 日历 ICS。取数与转换衔接，不增加第二套导出器，也不连接 Google/Microsoft 账号。

## 读取本人理论课表

已配置学校统一账号中的教务会话后，直接调用 `get_academic_timetable(semester="2026-2027-1")`，或运行：

```sh
stu-mcp timetable
stu-mcp timetable --semester 2026-2027-1
```

学期仅为示例，以学校表单实际提供的选项为准。省略参数读取学校选中的学期，返回真实学期选项及全部周次；指定不存在的学期会报错。结果包括课程、每组安排的星期／周次／节次、教师／地点、未排课项目和待核实项。它按需联网，复用 JW 会话，不额外下载成绩、不新增课表缓存或后台任务。

理论课表没有覆盖实验课、最新校历、节次实际时刻和专项调课。查询成功不自动表示可以导出完整学期文件：把 `courses` 原样交给旧输入模型，再由原 Skill 核对依据和缺口，详见[输入映射](../src/stu_mcp/skills/stu-timetable-export/references/reviewed-input.md#从教务读取结果组装)。

## 默认行为

OA 专项调课检索默认关闭；用户明确开启才执行，不每轮询问。关闭不阻塞正常校历模式导出，但报告为未检索，不能据此宣称没有额外调课。用户已提供的通知仍按适用范围使用，已知冲突不能忽略。

每次重新核对[官方校历目录](https://jwc.stu.edu.cn/wdxz/jxxl.htm)、目标学期发布/修订页和原附件，选择该学期最新有效版本，而非固定学年或列表第一条。校历、时刻表和课表的依据由 agent 核实；JSON 中声明“最新/完整”不代表转换器已联网核验。详细取证顺序、官方格式文档入口和输入字段以[技能源文件](../src/stu_mcp/skills/stu-timetable-export/SKILL.md)及其按需参考为准，本文不重复维护同一份操作清单。

## 代码与技能的职责

| 位置 | 职责 |
| --- | --- |
| `features/jw/timetable.py`、`JwAdapter` 与 JW 服务 | 当前学校表单、理论课表纯解析与按需读取；与成绩／考试共用来源会话和传输，不复制认证实现 |
| `features/timetable/export.py` | 唯一转换核心：校验已核对输入、展开课次、应用例外、检查冲突和生成 CSV/ICS；只用 Python 标准库，不访问学校或日历账号 |
| `skills/stu-timetable-export/SKILL.md` 与 `references/` | agent 的取证、审阅和目标格式工作流；不承担第二份日期或课次算法 |
| `scripts/build_timetable.py` | 薄运行入口；在仓库/安装环境调用同一核心，在导出资源包中调用附带的核心副本 |
| `skill_export.py` | 可选分发：从同一核心生成包内 `scripts/_timetable_core.py`，不手工维护两套实现 |

## 使用与分发

已安装 STU MCP 的本机可以使用随包技能资源；是否在客户端发现、安装或启用技能，按该客户端支持方式处理。生成 ZIP 不会自动安装技能或注册 MCP。源码技能源目录的薄脚本依赖项目核心，单独复制这个目录不足以独立运行。

需要独立资源包时执行：

```sh
stu-mcp skill-export --skill stu-timetable-export
stu-mcp skill-export --skill stu-timetable-export --apply
```

首条只预览，第二条生成用户数据目录下的 `exports/stu-timetable-export.zip`。这是**可选的本机命令资源包**：包含技能、参考、薄脚本、由项目核心生成的脚本副本和 `runtime.json`。`runtime.json` 指向生成机器的 Python 路径，换机、升级或重建安装环境后应重新导出并按客户端方式替换旧技能；本命令不承诺各客户端原生支持 ZIP 导入，也不是通用安装器。原 `connect ...` 与 `stu-campus.zip` 默认行为保持。

包内不含凭据、个人课表或登录态。资源可运行、客户端能使用技能、学校取证完成、目标 App 导入正确是分别核验的事项。

## 转换器范围

按[输入契约](../src/stu_mcp/skills/stu-timetable-export/references/reviewed-input.md)整理已经核对的 JSON，在新目录运行入口：

```sh
python path/to/stu-timetable-export/scripts/build_timetable.py --input reviewed.json --output-dir new-export --format all
```

支持明确周次、连续节次、课程/授课安排身份、教师/地点、取消、改期和显式来源日期处理的全日替换。现代学期采用明确 UTC+08 时刻，不依赖主机时区或 Windows tzdata。校历/课表未确认、有待核实项或冲突时不生成正式文件；某目标不能无损表达时报告部分成功，不丢课。

输出为 `review.json`、`schedule.ics`、`wakeup.csv` 与 `wakeup-settings.json`。WakeUp 的学期起点、周数和节次时刻需按设置文件单独核对；文件有效不等于实际 App 导入正确。WakeUp、Google Calendar、Outlook 的真实导入仍未验收。重复导入不承诺去重/覆盖，文件导入不自动同步，也不创建、覆盖或删除远端事件。转换器历史验证见[原课表记录](verification/2026-10-20-timetable.md)，新增读取的验收另行记录。

## 当前数据的范围

| 现有能力 | 实际范围 | 不能据此证明 |
| --- | --- | --- |
| `get_academic_timetable`（当前源码） | 本人指定学期的理论课表，全周次，含未排课及读取范围 | 实验课、最新校历、节次实际时刻及专项调课已核对 |
| `get_courses` | MySTU/雨课堂最新可用学期课程库存，含身份、名称、教师和来源原生学期 | 周次、星期、节次、日期和完整学期安排 |
| `get_schedule` | MySTU 个人日程，刷新过去7天至未来31天，含起止时间和地点 | 全学期、调课已覆盖、日程与课程一一对应 |
| `get_exams` | 教务考试安排，时间保留学校原文 | 日常授课和可导出的精确事件时间 |

不能把短期日程缓存命名为完整学期课表，或由课程名、考试时间推导授课安排。新增理论课表读取不改变上述工具参数、清理范围或原生学期语义。

## 独立的课表领域

课表来源归一化、依据校历展开事件和目标格式导出分别维护。学校表头／表单变化影响 `features/jw`，目标文件格式变化影响 `features/timetable/export.py`。CLI 与 MCP 调用同一个读取服务；Skill 负责取证和审阅，不实现第二份解析或日期算法。

一门课程可能有多组安排，查询保留每组安排身份，供同一转换器生成事件 UID。教师或教室改变不改变安排 ID；周次结构改变会产生新 ID，重新导入仍不承诺更新或去重。学校学期、教学周、自然日期分别取证，雨课堂整数 term 不自动解释成教务学期或周次，不按查询日期猜第一周。

本轮真实读取、空学期、未对应计划教师明细及合成测试见[理论课表验收](verification/2026-10-23-academic-timetable.md)。

同名课程、不同教学班、多教师/教室、离散周次和跨日安排不能自动合并。保留原始时间表达、歧义、未公布值和部分读取；缺失或冲突阻止受影响导出，完整空课表与失败分开。

## 扩展范围的核验条件

后续增加实验课、其他课表来源或新的导出目标时：

1. 在授权范围内确认实际课表入口、来源、登录依赖、学期选择和完整性证据；共享登录不证明业务相同。
2. 核对目标学期最新有效校历、第一教学周、校区节次时刻表及调停补课规则；只读已有个人日程不足以完成。
3. 用足以验证字段和实际安排的样本确定契约，真实个人页面与账号不进入仓库；自动回归使用合成数据。
4. 确认目标产品、版本和导入方式，读取当前官方格式说明或用户的可用样本，再实现格式。WakeUp 不猜原生备份/JSON；Google/Outlook 使用各具体产品官方导入说明。

回归覆盖来源字段漂移/歧义、分页与身份、同名不同班、周次/节次、跨月跨年/时区、调停补课、转义与重复导出；解析失败不得删除未知缓存或输出看似完整文件。合成验证、学校真实取数和各 App 真实导入分开记录，分别检查日期、时刻、教室、例外和重复导入。未来远端写入须另有相应授权与变更预览，生成文件不附带账号或写入权限。
