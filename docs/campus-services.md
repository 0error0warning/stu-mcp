# 校园入口、功能分类与认证关系

本目录整理学校业务入口与开源 stu-mcp 的对应关系，更新于 2026-10-23。先说明配置哪些登录后能用哪些功能，再核对学校服务、入口和接入缺口；认证与网络细节供维护时使用。Hermes 私有 `school_hub` 不在此范围。

版本范围：下文对应 v0.7.0，包含统一账号命令 `login school`、配置分组能力目录及私密设置页。入口调查及用途证据保留各自原日期，新增引导不构成新的学校业务实测。

本轮从[郁金香校园导航](https://d.stulip.org/)发现入口，再对照[学校快速通道](https://www.stu.edu.cn/kstd.htm)、网络中心和图书馆等官方说明。全部扫描范围、原始标签、公开旁证及匿名访问结果见[本轮调查](verification/2026-10-22-campus-entries.md)与[逐项清单 CSV](verification/2026-10-22-campus-entries.csv)。这份分类不是“全部学校系统已经接入”的承诺，也不是最新在线状态表。

## 配置哪些登录，当前能用哪些功能

用户只需选择自己要用的登录或配置项，查看对应功能。下表列当前已实现的范围；学校还有哪些服务尚未接入，集中在下一张表。

| 用户配置组 | 当前 MCP 功能 | 当前配置入口与条件 |
| --- | --- | --- |
| **无需学校登录** | 官网/学生处新闻通知、允许匿名读取的 OA 列表/正文/附件、校园入口查询、两种网络诊断；第三方狐友公开讨论和充电状态 | 直接查询；运行主机须能访问对应站点，目标内容须允许匿名读取。目录查询只提供入口，不办理该站业务 |
| **学校统一账号（CAS）** | 教务：成绩、加权统计、考试；MySTU：课程、作业/测验/资料、个人日程及课程所属 ELC/Campus；桑浦山宿舍报修：草稿、完整预览、确认后单次提交和该草稿的回执核查 | 设置页一次输入，连接全部已接入业务，内部各自保存会话。CLI 可用 `stu-mcp login school`，保留 `--services` 和教务兼容参数；原单业务命令保持兼容 |
| **WebVPN 登录** | 为当前 OA 适配器提供另一条访问通道；可选按需自动重登 | 主表单可填写已有令牌密钥，程序生成动态码并验证登录；也可使用当前动态码。CLI `login webvpn` 和 `webvpn-auto configure` 保持兼容。门户登录不保证 OA 正文/附件可读；能匿名直读时不需要配置 |
| **雨课堂授权** | 雨课堂课程、作业/测验、活动/资源和课程公告 | `stu-mcp login yuketang`，本人手机确认官方二维码 |
| **对分易授权** | 课程选择、本人明确启动的监听及结果查询 | `stu-mcp login duifene`，沿用原微信回调；登录不新建监听计划，新课堂实际提交仍待验收 |
| **外卖平台配置（实验）** | 商家、菜单、配送批次、规格及非交易选餐 | `stu-mcp takeout configure --file …`，宿主导入第三方配置；不使用学校登录，不下单或支付 |
| **本地工具维护** | 安装接入、更新检查/升级、本地待办、个人偏好、课表文件转换 | 不需要学校登录；不是学校业务授权。课表转换不代表已自动取得完整学期课表 |

统一账号 CLI默认选择 `jw`、`mystu`、`repair`，只向本人索取一次账号密码，再调用各业务独立的认证与成功证明；普通密码不持久保存，也不复制其他业务 Cookie。仅需部分功能时可用 `stu-mcp login school --services mystu repair`。教务兼容默认关闭；未在本次添加 `--allow-http-callback`、也未由本人预先开启持久兼容时，教务会报告未完成，其他业务可分别继续。

本机设置页默认在自己的浏览器打开，学校账号、雨课堂、对分易和 WebVPN 各为一个配置入口，在同一工作区输入或完成授权；它直接复用 HTTP 核心，不模拟终端，不经 MCP 收取密码、二维码或回调。配置后汇总展示「已配置」或未完成原因，不再另列单业务会话管理；功能说明与接入缺口来自同一能力目录。CLI 始终完整可用，只查看目录不会发起登录。

已保存会话只有在本地账号关联一致且本地状态未过期时才跳过认证，返回 `skipped=true, verified_live=false`，不代表学校服务器仍接受该会话。读取提示失效时，可用 `stu-mcp login school --services mystu --reauthenticate` 强制重新认证所选业务。旧版没有账号关联的会话需重新证明；认证未通过时保留旧会话与缓存，并明确它们不一定属于本次账号。单业务 CLI 登录和退出保持兼容，页面统一按配置组操作，详见[认证说明](authentication.md#统一账号与网页配置)。

已有功能也有范围：教务暂不含完整课表、选课、评教；MySTU 个人日程是过去 7 天至未来 31 天；`repair` 不覆盖 `r` 网络报修或任意历史工单管理；WebVPN 配置只服务已适配的 OA 路径，不自动增加其他校内查询。详见[教务](academic.md)、[雨课堂](yuketang.md)、[报修](repair.md)、[课表](timetable.md)、[对分易](checkin.md)、[外卖](takeout.md)及[OA 读取条件](verification/2026-10-22-oa-entry-boundaries.md)。

状态须分别显示：已有配置、已保存会话、当前网络可达、业务读取成功；不能将“已配置账号”直接写成“全部功能现在可用”。认证状态失效只影响依赖它的功能，公开来源继续独立读取。

## 对齐学校服务：入口与未接入清单

接入程度统一为 **业务已接入 / 入口导航 / 未接入**；网络诊断另标为工具能力。共享认证入口只负责归组，不能把学校已有服务算成 MCP 已有功能。

下表沿用现有 `school_service_portal`、`campus_repair`、`network_account` 等目录标识；标“候选”的标识只用于整理，尚非可调用的来源、工具或登录命令。具体 URL 路径、认证依据与历史日期仍保留在[逐项清单](verification/2026-10-22-campus-entries.csv)，不用主机名直接推断接入程度。

| 学校服务 / 标识 | 明确入口与用途 | 登录归组及证据 | MCP 当前缺口与下一步 |
| --- | --- | --- | --- |
| 一网通办 `school_service_portal` | [service /fe/](https://service.stu.edu.cn/fe/)，事项目录、条件、部门和办理目标 | 10/18 查看过登录后的网络专题；公开目录的实际读取条件需单独核实 | **入口导航**；先适配只读事项与“立即申请/跳转办理”目标，不把所有后端业务合成一个接口 |
| 校园综合报修 `campus_repair` | [r](https://r.stu.edu.cn/)，含两校区网络、应用及设施等故障 | 学校 SSO；10/18 实际查看表单，另有官方指南 | **入口导航**；独立验证 HTTP 认证及本人请求/状态只读，不由已有 `repair` 工具代办 |
| 上网账号/套餐 `network_account` | [netms](https://netms.stu.edu.cn/)，流量与账号服务 | 本轮根入口匿名跳 SSO；未认证或读个人业务 | **入口导航**；先核实套餐、余额、到期字段，改密/订购另行评估 |
| 学生事务 `student_affairs`（候选） | [xg](https://xg.stu.edu.cn/)，学生事务与当期开放事项 | 本轮根入口匿名跳 SSO；用途有官方快速通道/指南依据 | **未接入**；先核对本人可访问菜单与事项，不凭系统名认定综测、奖助、请假等均已覆盖 |
| 宿舍管理 `dorm_management`（候选） | `dorm.stu.edu.cn`，导航标宿舍管理/查询 | 本轮根入口匿名跳 SSO；具体用途与现行办理系统待核实 | **未接入**；核实与 `xg` 的实际分工；宿舍管理与设施报修分别登记 |
| 宿舍水电 `dorm_utilities`（候选） | `power.stu.edu.cn`，水电查询 | 官方新生指南列用途；本轮根入口匿名跳 SSO | **未接入**；核实现行安全入口、本人房间关联及实际可读的余额/用量 |
| 馆藏检索 `library_catalog`（候选） | [opac.php](https://opac.lib.stu.edu.cn/opac.php)，书目及馆藏 | 馆方说明可公开检索；不是读者中心的登录条件 | **未接入**；优先匿名查询，验证分馆、分页、零结果和字段；本机连通失败不能写成永久不可用 |
| 数据库目录 `library_resources`（候选） | [资源导航](https://www.lib.stu.edu.cn/zy/database)，资源用途和访问说明 | 公开目录；订购内容另有 CARSI/WebVPN 等路径，尚未认证验证 | **未接入**；先读目录与访问条件，订购全文权限另核实 |
| 本人借阅 `library_reader`（候选） | [读者中心](https://opac.lib.stu.edu.cn/web/index.html?type=reader)，借阅与到期 | 馆方说明有馆内账号/一卡通及 MySTU 方式；实际登录链未验 | **未接入**；先验证登录与本人借阅只读，续借/预约属于后续独立动作 |
| 图书馆空间 `library_space`（候选） | [newic](https://app.lib.stu.edu.cn/newic/)，空间预约 | 官方首页提供入口；实际认证未核实 | **未接入**；先核实校区、空间对象、时段和登录入口，再评估预约 |
| 校内其他预约（候选） | [ehall 预约](https://ehall.stu.edu.cn/yy-sys/pc/home)、[booking](https://booking.stu.edu.cn/)，以及导航所列 `classroom`/ELC-CILL | 对象和认证逐项确认；`classroom` 有匿名 SSO 跳转，ELC-CILL 预约尚未验 | **未接入**；按具体业务/路径分别登记，不将同 MySTU 域下的预约算作课程活动已适配 |
| 校园卡、邮箱及其他管理系统（候选） | `smartcard`、官网 Outlook 入口、教学质量/科研/财务等 | 各有账号用途与权限；同一学校账号不证明协议或业务相同 | **未接入**；按学生实际需求逐项确定功能与认证，完整线索见 CSV |

优先顺序为：**公开事项目录、馆藏与资源目录 → `r` 请求查询 → 水电/流量/学工只读 → 借阅与预约**。正式接入前先验证纯 HTTP、本人身份或明确匿名范围、字段及分页/空态；涉及提交、续借、预约、充值、改密等动作时，再单独设计确认和回执。

## 背后维护的对应关系

维护一份小型服务目录即可支持“按功能找入口”和“按配置看能用什么”两个视图。每个条目至少记录：

| 信息 | 作用 |
| --- | --- |
| 学校业务标识、名称、校区与入口路径 | 保持 `repair`/`r`、公开馆藏/个人借阅、课程/预约等业务身份独立；别名只用于检索 |
| 功能及接入程度 | 写清现已实现、仅导航、待接入；关联已有来源和工具，不由 URL 存在推断可用 |
| 登录配置及认证归组 | 统一账号组关联 `jw/mystu/repair` 各自登录 ID，`webvpn/yuketang/duifene` 和第三方配置独立；归组不合并业务会话 |
| 网络访问条件与来源会话 | 与账号配置分别记录；同一服务可有匿名直读及 WebVPN 等不同路径 |
| 证据日期、范围和下一验证 | 区分官方用途、匿名跳转、实际认证、只读业务和正式写入；未知状态保持未知 |

`capability_catalog` 维护统一静态映射，并从已读取的本地状态生成 `profiles`（配置→功能）和 `services`（具体业务→接入程度）两种视图。`App.status()`、`HostRuntime.capabilities()` 与宿主设置页共用此目录，旧字段和 47 项工具接口保持兼容；`SOURCES` 仍只含七个采集来源。目录本身不登录、不联网、不启动签到后台，也不把新增条目注册为来源、认证白名单或网络检测目标。

目录把当前访问与业务读取标为 `not_checked`；已保存会话、本地后台状态和历史刷新分别展示。`implemented`、`navigation_only`、`not_integrated` 分别表示已有业务适配、仅导航和未接入，不能通过学校账号配置把后两类变成可用业务。未知认证的图书馆借阅、预约等路径仍保留未核实标记。

## 认证关系：横向标签，不是业务合并

一个业务可有多种认证方式；同一认证入口也可服务多个业务。校园账号相同、页面能跳转到 SSO、业务会话可读，是不同证据。

| 认证关系 | 已确认的范围 | MCP 会话与未验边界 |
| --- | --- | --- |
| 学校 CAS SSO：已认证业务 | 教务、MySTU、`repair` 正式 HTTP 认证于 10/21 验收；`r` 的 SSO 登录于 10/18 人工查看表单，另有官方指南 | 教务、MySTU、`repair` 共用 CAS 协议代码，业务会话和成功证明独立；`r` 只有历史人工表单核验，没有 HTTP 业务适配器 |
| 学校 CAS SSO：匿名跳转线索 | 本轮 `netms`、`dorm`、`power`、`xg`、`carfleet`、`classroom`、`hr`、`lrmo`、`sro` HTTP 入口返回 302 到学校 SSO | 仅 `anonymous_redirect` 层级；没有输入凭据、核对身份或读取业务。旧域名仍跳 SSO 不证明业务仍受理 |
| 一网通办登录 | 10/18 登录后查看网络专题，访问策略记录 SSO 依赖 | 只有导航与既有证据；本轮公开首页可读，不等于登录或专用业务适配验收 |
| WebVPN 密码及已绑定 TOTP | 10/21 纯 HTTP 正式 CLI 认证、配置和资源目录通过 | 独立 `webvpn` 会话，用于对应访问通道；OA 公告匿名直读不需要它，WebVPN 登录也不等于员工办公登录 |
| 雨课堂官方二维码 | 10/21 本人手机确认、HTTP 交换、绑定状态与课程读取通过 | 独立 `yuketang` 会话；服务器不用浏览器，人工手机授权仍需要 |
| 对分易原微信回调 | 既有固定回调交换；CLI 和网页复用同一 worker | 不混用其他官网 QR/SignalR 路线；本轮不宣称重新完成真人授权或课堂签到 |
| 图书馆账户 / MySTU；CARSI | 馆方公开说明支持多入口；CARSI 学校身份路由另有馆方说明 | 尚未实际认证，不能借用现有 MySTU、CAS 或 WebVPN 会话推断成功 |
| 其他校园账号用途 | `a`、邮箱、校园卡等官方说明 | 同一账号不证明同一协议。认证方式、额外密码、MFA 和实际权限待各系统验证 |
| 匿名与独立第三方授权 | 官网、学生处、公开 OA、狐友、充电、诊断；外卖独立签名配置 | 分别遵守来源范围；不为公开查询提前要求学校账号 |

当前源码的 `source` 是数据来源，`session` 是认证状态归属；例如 OA 经 WebVPN 路径读取时使用 `webvpn` 会话，匿名公告不使用该会话。引导优先说明[OA 能读什么、什么条件下能读](verification/2026-10-22-oa-entry-boundaries.md)，无需用户先辨认内部认证链。统一账号命令只为明确选中的已适配业务逐项认证，不能据此批量复制 Cookie、登录未接入来源，或把“已登录 SSO”显示成“全部业务可用”。具体 HTTP、Moodle、回调及退出屏障见[认证与会话边界](authentication.md)。

| 入口 | 用途及证据 | 实际验证范围 |
| --- | --- | --- |

学校快速通道和 2023 年东海岸指南称 `r` 为“东海岸网上报修”，10/18 实际表单则包含两校区。二者保留各自证据，不能只凭旧标题限制为东海岸，也不能宣布 `r` 已正式替换 `its`。`repair` 的实际学生表单没有故障类别下拉框，不能使用 `r` 分类字段替它填表。

`repair` 首页保留的网络报修说明指向 `its`；这不把宿舍表单变成网络工单表单，也不证明这条引用是当前唯一渠道。本轮没有为更新目录重复登录或提交任何工单。原用户浏览器已完成的真实提交不能替代新 HTTP 最终写入与学校回执的验收，详见[10/21 正式实现验收](verification/2026-10-21-http-default.md)。

### 网络故障表单的已核验步骤

以下是 2026-10-18 实际查看的路径，后续页面可能变化：

1. 打开 `https://r.stu.edu.cn/`，点击“SSO单点登录”，完成学校统一认证。
2. 进入“请求”，点击“新建”。
3. 按实际情况选择校区，在“分类”选择“网络故障”。

## 目录查询、网络证据与后续引导

`get_service_links` 与 `stu-mcp query service --source public` 当前合并官网缓存和四个维护入口（`r`、`repair`、`its`、一网通办）；无官网缓存也能查询这四项。本文及扫描 CSV 新增的候选没有自动加入运行时目录。网络故障检索推荐已查看表单的 `r`；`its` 保留原有引用、`migration_confirmed=false`，不改写为已废弃。

运行时按精确主机补充用途、校区和证据；原缓存标题放在 `original_title`，不让旧标签或引用其他系统的说明制造错误命中。维护目录 `collected_at=null`，官网缓存保留自己的采集时间；`purpose_verified_on` 是用途核验日期，`form_verified_on` 是表单证据日期，均不能替代最新连通检查。查询链接本身不探测站点，仍为 `availability=not_checked`。未知主机不按相似域名猜用途。

校园 HTTP 使用 `trust_env=False`，不继承环境代理；这不表示已绕过 TUN、系统路由或 DNS。保持单站点与认证依赖分别诊断，HTTP/HTTPS 分别观察；校内/校外仅用用户提供的位置提示。DNS、TLS、超时或观测工具抓取失败不能直接写成学校停服、永久限校内或已迁移，也不自动修改代理、DNS、路由、hosts 或证书校验。

后续入口配置应复用这份任务分类：先确定用户的任务、校区和对象，列出匹配系统，再解释该功能实际需要的认证与访问条件。优先补公开目录和只读查询，再分别评估个人业务；预约、续借、充值、改密、申请和报修提交各有自己的确认与回执边界。现阶段不把发现入口直接当作已授权实现或已验证业务。
