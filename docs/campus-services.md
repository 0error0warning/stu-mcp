## 已核验到表单的网络故障报修路径

1. 打开 `https://r.stu.edu.cn/`，点击“SSO单点登录”，完成学校统一认证。
2. 进入“请求”，点击“新建”。
3. 按实际情况选择“校区”，在“分类”选择“网络故障”。
4. 填写必填的详细故障地址、联系人电话、预约时间和主题，在描述中说明故障现象。
5. 页面提供“添加请求”按钮；本轮停在表单核验，没有点击提交，没有确认后台受理或处理时限。

此外实际分类列表还包含应用系统故障、一卡通故障、电话、多媒体教室设备故障、门禁道闸故障、监控设备故障以及多类设施故障；类别存在不表示本项目已验证各类工单受理。

官方指南另列微信小程序“汕大报修”。这是其他入口线索，本轮未打开小程序，不保证其当前分类和提交情况；MCP 的 `alternate_channels` 明确标为 `official_guide_only`。

`repair` 首页仍提示：“网络方面等报修，请登录校园网自助服务平台：http://its.stu.edu.cn”。实际学生表单只有标题、发生地址、设备名称、详细描述、预约时间等，没有故障类别下拉框，也没有“校园网故障”分类。不能因为它叫“网上报修”就把它当作网络工单入口，也不能把这条原有提示当作当前唯一渠道。

本次在 STU 校园网用不携带登录态、显式不使用代理的请求探测 `its`：域名解析到校内 IPv4，HTTP 连接被拒绝，HTTPS 连接超时。该结果只覆盖当时客户端到该地址的连接，不证明站点已停用、已迁移，亦不能反推真实报修步骤。`repair` 与 `r` 的匿名 HTTPS 直连可达；`repair` 进入学校统一认证页。真实账号、CAS ticket、会话、个人页面和截图不随仓库分发。

若网络报修入口无法访问，可按[网络中心官方联系方式](https://info.stu.edu.cn/its/lxwm.htm)联系：桑浦山 `0754-86503400`（校园网业务按 1），东海岸 `0754-86500115`；邮箱 `stunic@stu.edu.cn`。电话来源是官方服务说明，不是本轮电话拨测结果。

## MCP 查询与直连

`get_service_links` 与 `stu-mcp query service --source public` 合并官网缓存和维护的三个报修入口、一网通办目录。即使尚无官网缓存，也能查询这四个入口。网络故障检索先返回 `r`（`service_id=campus_repair`、`recommended=true`），`its` 保留为不推荐的原有引用，`migration_confirmed=false`；不把它改写为已正式停用。按精确主机补充用途、校区和来源证据；原始缓存标题保留为 `original_title`，不参与已分类入口的正向检索。先合并和筛选再分页，防止旧标题或引用其他系统的说明造成错误命中。

维护目录的 `collected_at` 为 `null`，官网缓存沿用自己的采集时间；`purpose_verified_on` 只表示用途核验。`r` 单独记录 `form_verified=true`、核验日期、分类、校区和表单路径；`submission_verified=false`、`workflow_verified=false` 表示未验证提交/受理的完整流程，不能反过来解释为未查看表单。`its.last_connection_check` 仅保留当次匿名直连失败的证据。查询本身不探测站点，`availability=not_checked`，不把维护或列表刷新日期当作此刻在线的证据。未知主机仍标为用途未核验，不能按标题或相似域名猜测。

`CampusHTTP` 已使用 `trust_env=False`，不继承 HTTP/HTTPS/ALL_PROXY 环境变量。它不关闭系统代理、不改 Clash，也无法据此保证绕过 TUN、系统路由或 DNS。新增 `diagnose_campus_network` 分别检测业务站、SSO、匿名直连、系统DNS和本机代理；校内/校外位置只用用户提示，详见[四种环境的处理](network.md)。对一个站点的失败不推断其他站点相同，不全局关闭代理或放宽来源主机、HTTP 会话策略。

2026-10-19 增加[宿舍报修预览、确认与提交](repair.md)，仅适配独立的 `repair` 表单。默认不提交，必须展示实际完整表单并等待本轮用户确认，才允许一次匹配的正式请求；提交后核对新增列表单号、完整详情及处理状态，也可只读恢复。用户原浏览器已真实提交成功，原生 MCP 整单提交仍待真实验收。没有修改已有工单或导入浏览器保存的凭据。`r` 的分类证据不能作为 `repair` 的填表字段。保留学校 HTTP 旧链接也不代表允许 MCP 向它发送凭据或会话。
