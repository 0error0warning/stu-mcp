# 校园入口、功能分类与认证关系

本目录整理学校业务入口与开源 stu-mcp 的对应关系，更新于 2026-10-22。以用户想完成的任务分类；系统名称、认证方式、访问条件和 MCP 接入程度分别记录。Hermes 私有 `school_hub` 不在此范围。

本轮从[郁金香校园导航](https://d.stulip.org/)发现入口，再对照[学校快速通道](https://www.stu.edu.cn/kstd.htm)、网络中心和图书馆等官方说明。全部扫描范围、原始标签、公开旁证及匿名访问结果见[本轮调查](verification/2026-10-22-campus-entries.md)与[逐项清单 CSV](verification/2026-10-22-campus-entries.csv)。这份分类不是“全部学校系统已经接入”的承诺，也不是最新在线状态表。

## 分类与接入程度

“查作业”可能同时需要 MySTU 和雨课堂；“查通知”可能涉及官网、学生处和 OA；“预约”则要先区分场地、图书馆空间、活动等对象。用户任务与业务系统是多对多关系，不要求用户先理解内部来源名。

本文使用三个接入层级：

- **业务已接入**：已有专用 MCP/CLI 适配器；仍以各功能的验证范围为限。
- **入口导航**：能提供链接、用途或办理步骤，没有该系统的业务读取/提交适配器。
- **未接入**：本轮发现的候选；文档收录不表示运行时已经能搜索、登录或查询它。

诊断工具另标“诊断已接入”，不属于学校业务适配。入口返回 200、跳到认证页或列在官网上，都不能证明登录后的功能已完成验收。

## 认证关系：横向标签，不是业务合并

一个业务可有多种认证方式；同一认证入口也可服务多个业务。校园账号相同、页面能跳转到 SSO、业务会话可读，是不同证据。

| 认证关系 | 已确认的范围 | MCP 会话与未验边界 |
| --- | --- | --- |
| 学校 CAS SSO：已认证业务 | 教务、MySTU、`repair` 正式 HTTP 认证于 10/21 验收；`r` 的 SSO 登录于 10/18 人工查看表单，另有官方指南 | 教务、MySTU、`repair` 共用 CAS 协议代码，业务会话和成功证明独立；`r` 只有历史人工表单核验，没有 HTTP 业务适配器 |
| 学校 CAS SSO：匿名跳转线索 | 本轮 `netms`、`dorm`、`power`、`xg`、`carfleet`、`classroom`、`hr`、`lrmo`、`sro` HTTP 入口返回 302 到学校 SSO | 仅 `anonymous_redirect` 层级；没有输入凭据、核对身份或读取业务。旧域名仍跳 SSO 不证明业务仍受理 |
| 一网通办登录 | 10/18 登录后查看网络专题，访问策略记录 SSO 依赖 | 只有导航与既有证据；本轮公开首页可读，不等于登录或专用业务适配验收 |
| WebVPN 密码及已绑定 TOTP | 10/21 纯 HTTP 正式 CLI 认证、配置和资源目录通过 | 独立 `webvpn` 会话，用于对应访问通道；OA 公告匿名直读不需要它，WebVPN 登录也不等于员工办公登录 |
| 雨课堂官方二维码 | 10/21 本人手机确认、HTTP 交换、绑定状态与课程读取通过 | 独立 `yuketang` 会话；服务器不用浏览器，人工手机授权仍需要 |
| 对分易原微信回调 | 既有固定回调交换；CLI 和网页复用同一 worker | 不混用其他官网 QR/SignalR 路线；本轮不宣称重新完成真人授权或课堂签到 |
| 图书馆账户 / MySTU；CARSI | 馆方公开说明支持多入口；CARSI 学校身份路由另有馆方说明 | 尚未实际认证，不能借用现有 MySTU、CAS 或 WebVPN 会话推断成功 |
| 其他校园账号用途 | `a`、邮箱、校园卡等官方说明 | 同一账号不证明同一协议。认证方式、额外密码、MFA 和实际权限待各系统验证 |
| 匿名与独立第三方授权 | 官网、学生处、公开 OA、狐友、充电、诊断；外卖独立签名配置 | 分别遵守来源范围；不为公开查询提前要求学校账号 |

当前源码的 `source` 是数据来源，`session` 是认证状态归属；例如 OA 经 WebVPN 路径读取时使用 `webvpn` 会话，匿名公告不使用该会话。引导优先说明[OA 能读什么、什么条件下能读](verification/2026-10-22-oa-entry-boundaries.md)，无需用户先辨认内部认证链。UI 可以展示“统一认证”筛选，但不能据此批量复制 Cookie、自动给所有来源登录，或把“已登录 SSO”显示成“全部业务可用”。具体 HTTP、Moodle、回调及退出屏障见[认证与会话边界](authentication.md)。

### 网络故障表单的已核验步骤

以下是 2026-10-18 实际查看的路径，后续页面可能变化：

1. 打开 `https://r.stu.edu.cn/`，点击“SSO单点登录”，完成学校统一认证。
2. 进入“请求”，点击“新建”。
3. 按实际情况选择校区，在“分类”选择“网络故障”。
4. 填写必填的详细故障地址、联系人电话、预约时间和主题，在描述中说明故障现象。
5. 页面提供“添加请求”按钮；当日核验停在表单，未验证提交、后台受理或处理时限。

当时分类还包含应用系统、一卡通、电话、多媒体教室、门禁道闸、监控设备和多类设施故障。类别存在不表示各类受理均已验收。官方小程序只核实指南提及，MCP 标为 `official_guide_only`，没有打开或适配小程序。

入口无法访问时，可查[网络中心官方联系方式](https://info.stu.edu.cn/its/lxwm.htm)：桑浦山 `0754-86503400`，校园网业务按 1；东海岸 `0754-86500115`；邮箱 `stunic@stu.edu.cn`。这里只引用公开说明，未拨测。

## 目录查询、网络证据与后续引导

`get_service_links` 与 `stu-mcp query service --source public` 当前合并官网缓存和四个维护入口（`r`、`repair`、`its`、一网通办）；无官网缓存也能查询这四项。本文及扫描 CSV 新增的候选没有自动加入运行时目录。网络故障检索推荐已查看表单的 `r`；`its` 保留原有引用、`migration_confirmed=false`，不改写为已废弃。

运行时按精确主机补充用途、校区和证据；原缓存标题放在 `original_title`，不让旧标签或引用其他系统的说明制造错误命中。维护目录 `collected_at=null`，官网缓存保留自己的采集时间；`purpose_verified_on` 是用途核验日期，`form_verified_on` 是表单证据日期，均不能替代最新连通检查。查询链接本身不探测站点，仍为 `availability=not_checked`。未知主机不按相似域名猜用途。

校园 HTTP 使用 `trust_env=False`，不继承环境代理；这不表示已绕过 TUN、系统路由或 DNS。保持单站点与认证依赖分别诊断，HTTP/HTTPS 分别观察；校内/校外仅用用户提供的位置提示。DNS、TLS、超时或观测工具抓取失败不能直接写成学校停服、永久限校内或已迁移，也不自动修改代理、DNS、路由、hosts 或证书校验。

后续入口配置应复用这份任务分类：先确定用户的任务、校区和对象，列出匹配系统，再解释该功能实际需要的认证与访问条件。优先补公开目录和只读查询，再分别评估个人业务；预约、续借、充值、改密、申请和报修提交各有自己的确认与回执边界。现阶段不把发现入口直接当作已授权实现或已验证业务。
