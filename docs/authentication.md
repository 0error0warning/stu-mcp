# 模块职责与现有登录流程

本文以源码调用链为准，区分已接入能力、匿名网页调查与真实账号验收。它是修改认证或服务器部署前的基线；官网出现另一种登录方式，不表示本项目已经采用，也不授权替换现有流程。

**浏览器使用是当前适配器的实现事实，不是学校认证协议的必然要求。** 此前没有验证纯 HTTP 首次认证，不能写成已经尝试而不可行。本轮补做的 HTTP 匿名前置、原教务 requests 实现及尚缺的真实账号证明见[纯 HTTP 调查](verification/2026-10-21-http-auth.md)。后续先验证 HTTP，确有需要再使用无头浏览器，实际遇到人工挑战时再介入。

后续[真实验证](verification/2026-10-21-http-auth-live.md)已确认：教务、MySTU、桑浦山报修和雨课堂可在本次账号下通过纯 HTTP 首次认证及对应业务读取。
[WebVPN 继续复核](verification/2026-10-21-webvpn-http.md)也已通过纯 HTTP 密码、已绑定 TOTP 和认证后资源目录读取；OA 当前目录指定 HTTP 8118，先前 HTTPS 候选证书不匹配，正文尚未验收。不能再把此前 20113 当作当前认证结果。
该证据没有自动改变下文的现有产品实现，也未覆盖所有账号、ELC 活动、会话到期或服务器部署。

开源 `stu-mcp` 与 Hermes 私有 `school_hub` 分开维护。本文和本次服务器修正只涉及本仓库，不修改原 School Hub、Hermes 或生产账号。

主要来源的无浏览器认证可行性已基本验证；正式产品尚未全部切换，认证成功也不能替代全部业务和会话生命周期验收。

## 运行入口与状态归属

| 边界 | 实现与责任 |
| --- | --- |
| MCP | `server.build_server` 声明 38 项工具，统一处理脱敏错误；stdio 与私有 HTTP 使用同一组工具，不解析学校页面，不接收认证凭据 |
| 个人实例 | `hosting.HostRuntime` 拥有一个 App、报修草稿、诊断缓存和可选设置页。HTTP 多客户端共用这些对象，断开客户端不清空它们；单用户、单 worker，不是多租户 |
| 查询编排 | `App` 负责刷新、读取缓存、本地状态和来源版本检查；`collectors/parsers` 保留旧 Python 导入和依赖注入点 |
| 来源适配 | `features/*` 分离固定请求契约、纯解析与服务编排；解析失败、认证失败、确认空集与读取不完整不能互换 |
| 学校状态 | `Runtime` 定义目录和选项，`Vault` 保存来源会话，`Store` 保存缓存；`credentials` 默认系统 keyring，显式配置才启用外置主密钥加密后端 |
| 对分易 | `CheckinClient` 通过回环 HTTP 控制独立 `stu_checkin` worker；Controller 是唯一业务控制者，MCP、网页和 CLI 共用它，不各建一套登录/监听状态 |
| 人工浏览器 | `auth.interactive_login` 和报修适配器各自拥有临时浏览器。`interaction` 只检查这些手工浏览器的显示前提，不控制 HTTP 读取、微信回调或 WebVPN 无头重登 |
| 终端 | `terminal` 只在真实人工 TTY 隐藏接收认证输入。CLI 不提供凭据参数、环境变量或管道输入；MCP 永远不转发这些输入 |

## 各功能的认证与副作用

| 功能 | 现有认证 | 正常读取／操作 | 图形界面与后台 |
| --- | --- | --- | --- |
| 官网、学工处、服务目录 | 无账号 | 固定公开地址，按需读取、更新本地缓存 | 无浏览器、无持续任务；目录不是实时可达性证明 |
| OA 通知及附件 | 先匿名；受保护读取才使用 `webvpn` 会话及可选自动重登 | `notices.service.oa/article` → `protected_access`；受保护结果加密 | 读取无桌面；自动重登用无头 Chromium，人工挑战暂停 |
| 教务成绩与考试 | 独立 `jw` 会话，经学校 SSO | `JwAdapter` → 固定成绩/考试查询；部分 POST 是查询，不是业务提交 | 首次登录仍需人工浏览器；读取已有会话不需显示 |
| MySTU / ELC / 日程 | 独立 `mystu` 会话，经 SSO，并引导 ELC 会话 | `MystuAdapter` 读取 API 和已知页面；课程/活动/详情独立处理失败 | 首次登录仍需人工浏览器；无监听任务 |
| 雨课堂课程与活动 | 独立 `yuketang` 会话，在官方浏览器页面由本人登录 | `YuketangAdapter` 读取固定课程、活动、公告 API；活动与公告互不拖累 | 现有首次登录仍是人工浏览器，尚未接入 CLI 二维码认证 |
| 桑浦山宿舍报修 | 全新独立临时 context：`repair → SSO → repair` | 填表、回读、完整展示审核、本人确认后至多提交一次，随后核对新增记录和详情 | 当前仍需人工浏览器；不加载 Vault、不导入别的来源 cookies、不持久化临时登录 |
| 对分易 | **原微信 OAuth 回调链接** | 后台通过固定 `P.aspx` 换会话，验证课程后保存；只有用户要求监听才创建计划 | Web 与 CLI 可接收回调；不需要 Chromium。原已授权持续计划依旧可恢复 |
| 充电 | 第三方匿名签名，无学校账号 | 设备/插座只读查询、TTL 和租约缓存；不调用充电开关、绑卡、支付 | 无网页依赖、无后台任务 |
| 狐友 | 独立公开社区匿名签名 | 固定公开 GET；响应 cookies 不变成账号会话；本地合并帖子和回复 | 不登录、不发帖、不运行后台同步 |
| 网络诊断 | 无账号 | 固定匿名入口、DNS、可选明确代理对照；不跟随认证、不改配置 | 探测发生在 MCP 宿主，不代表客户端网络；有并发和时间上限 |
| 课表转换与技能 | 转换器无需账号 | `features/timetable/export.py` 只将已核对 JSON 转成 CSV/ICS 和报告；写本地文件，不写外部日历 | 无网络/浏览器。完整课表、最新有效校历须由技能另行核查，OA 专项检索默认关闭 |

`App.query`、成绩统计及普通缓存读取不会偷偷刷新或重新登录。个人缓存依然需要可用的解密后端。`set_task_status`、资料设置和课程快照清理只修改本地数据，不修改学校作业或课程记录。

## 学校来源：登录、证明、保存与失效

`CLI login jw|mystu|yuketang|webvpn` 或设置页 `/api/login` → `LoginJobs/interactive_login` → 临时 **headed** Chromium → 官方入口。程序不从对话获取账号密码，由本人在官方页面操作。

- **教务**：到已知学生主页后，`proof` 使用 `JW_HOME` 和 `jw_authenticated` 识别学生主页标记。`jw_http_compat` 默认关闭，必须由本人在设置中明确开启；密码仍只发 HTTPS，HTTP 教务客户端不使用 SSO cookies。
- **MySTU**：访问 `/user/validate`，再在同一浏览器进入 `/courses/elc/` 引导 Moodle 会话。此处登录证明仍有下文列出的薄弱点，不能写成所有 MySTU/ELC 功能均已验收。
- **雨课堂**：`proof` 实际请求学生课程接口，要求 `data.list`，不是仅凭主页或 cookies 存在认定登录。
- **手动 WebVPN**：门户状态只暂存，OA 的实际受保护访问另行验证，`verified_live=false` 不应被升级为 OA 已读通。

`scoped_state` 将浏览器状态收窄到该来源范围，再由 `Vault.save` 加密保存。各来源使用独立文件及版本；不得因为 SSO 相同就导入其他来源 cookies。保存会话、清旧缓存和退出登录都使用来源锁及随机 generation / 会话指纹，防止旧的在途登录把刚退出或新账号的数据写回。

`Vault.status` 是本地会话状态与过期时间检查，不是当前在线认证证明。业务 HTTP 层另行识别登录跳转、401、登录页面或平台认证错误；限流、权限不足、结构改变和网络错误不能一律报“登录失效”。退出通过 `App.logout` 移除指定来源会话与缓存，其他来源保留。

## WebVPN：复用原有无头重登

`webvpn-auto configure` 或本机设置页 → `WebVPNConfig.configure` → 批准的凭据后端。配置是可选、明确启用的行为，会断开原 WebVPN 会话并清旧 OA 缓存；不执行首次令牌绑定。终端入口只改变输入方式，没有另一套服务器认证协议。

受保护 OA 读取 → `protected_access` → 先复用会话 → 需要时最多一轮 `automatic_login(headless=True)` → 账号密码及已有 TOTP → 实际读取目标 HTTPS OA 资源 → 检查配置/会话代次 → 保存新会话与业务结果。仅到门户、看到 cookie 或填写完表单不算受保护资源验收。

认证跨进程串行，有失败冷却；密码/TOTP 每轮各尝试一次。账号拒绝、首次绑定、图片验证码及其他人工挑战会暂停，不 OCR、不模拟图形验证通过、不自动绑定令牌，也没有定时保活任务。本次补齐学校当前 `randCode` 命名的可见挑战检测；“动态口令”和四字符图片码是不同步骤。

## 对分易：沿用微信回调，不替换官网扫码

1. 网页或人工终端提供现有固定微信授权地址，由用户在微信完成授权。
2. 用户将含临时 `code` 的返回链接粘贴到本机网页，或在 `stu-mcp login duifene` 的隐藏输入中粘贴。CLI 非 TTY / 无法关闭回显会拒绝，不接受 `--link`、环境变量或 stdin 管道。
3. 校验对分易 HTTPS 地址及唯一的 32 位 code，只提取该 code，不访问用户输入的任意 URL。
4. CLI 发现/复用同一个后台，核对进程、实例和协议，通过原回环访问控制只发一次 `/api/connect`；不另起 Controller。后台链路仍是 `Controller.connect → Bridge.login_by_link → DuifeneApi.login_by_link → P.aspx`。
5. 后台实际获取并解析课程后才保存会话；持久化前的交换或课程验证失败恢复原内存会话，不用一次失败覆盖原加密状态。当前零课程账号不能通过这套成功条件。
6. CLI 只展示安全结果与当前监听状态。`confirmed` 要求本地后台 `/api/connect` 明确成功回执，再读取当前状态；不是仅凭 `P.aspx` 返回 HTTP 200。CLI 与后台之间的回执中断或无法解析按 `unknown` 处理，不重发，也不拿旧登录态冒充本轮成功。上游交换或课程读取失败仍沿用原 Bridge 回滚并返回失败，此时为 `rejected`，不表示必然是账号被拒绝。回执丢失也不能推导后台已回滚。

官网二维码 + SignalR 是本聊天匿名调查的**另一条未接入路线**。后台现有 SignalR 代码也不代表已接入官网扫码登录。此次不新增二维码登录、不更换原回调协议。

`Controller._run` 与回调成功后会按旧规则恢复已授权的持续计划：必须原计划启用、时长为持续、账号和课程匹配；换账号使旧计划失效。CLI 不调用选课或 start、不创建新计划，也不擅自取消原恢复设置。后台仍会按旧规则回显课程选择（没有旧匹配时可能显示全部可用课程），这不构成新监听授权。登录成功不表示签到成功。

后台使用进程锁、实例标识和回环发现；MCP 与网页共用 worker。只有明确认证失效才清会话，网络未知保留状态。普通 MCP 关闭不停止已授权 worker；显式 stop 先暂停再退出。注销清对分易会话、计划和记录，不代替学校来源注销。会话、计划和有限记录在独立 `state.enc` 加密保存；回调原文不持久化。

## 已识别的基线薄弱点

以下在服务器改造前已存在，应保留为独立的后续工作，不用未经核验的新字段或认证路线掩盖：

- **MySTU 登录 proof** 目前只否定 `authenticated=false` / `success=false`，HTTP 200 空对象也会通过。应取得实际成功响应契约后改为正证据；ELC bootstrap 也不能代替完整 Moodle 页面验收。此次不猜字段、不宣称 MySTU/ELC 已实测通过。
- **对分易失效通知竞态**：旧 `LoginSentinel` 检查释放认证锁到触发失效回调之间，新登录可能插入；需要认证版本屏障。补 CLI 不改变原恢复规则，也不宣称这个既有竞态已修复。
- **新课堂实际签到**、更多平台账号、会话失效恢复和真实服务器登录仍按[验证记录](verification.md)分别验收。合成用例、匿名二维码和协议握手不能充当账号或业务成功证明。
