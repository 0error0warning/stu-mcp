## uv 启动路径与课程同步修复（0.3.1）

0.3.0 的上述安装验证在 Windows 上进行，未覆盖 POSIX 下 uv Python 符号链接。Hermes 报告指出 `Path(sys.executable).resolve()` 会跳过虚拟环境，导致生成的启动命令无法导入 `stu_mcp`。修复保留原始 `sys.executable`，原有配置可通过重新接入更新。

`scripts/check_installed_runtime.py` 在全新的临时 `UV_TOOL_DIR` 安装构建的 wheel，从安装后的进程实际生成各客户端配置，使用配置中的原始命令进行 stdio 握手和工具发现，执行两种导出 Skill 的版本与状态命令。Linux/macOS 还确认该入口为符号链接、底层解释器确实无法导入包。所有文件与客户端配置写入临时目录，不使用学生账号或校园网络；CI 四个平台/版本均运行该检查。

课程同步使用合成 MySTU/雨课堂响应验证学期切换、确认空清单、单课程空活动、部分失败、课程上限、活动上限、分页标记、缺失字段、旧缓存迁移、状态保留与清理、加密范围元数据、来源退出隔离及事务回滚。真实个人来源仍需要学生验收。

本次 Windows 完整回归为 162 项通过、1 项系统符号链接测试跳过，Ruff 和补丁格式检查通过。隔离 wheel 的八种 stdio 配置均实际启动并发现 16 个工具，两种 Skill 的版本与状态命令实际执行通过。
