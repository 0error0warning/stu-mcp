# 已验证校园功能的分批接入方案

状态：**开始逐项接入，尚未发布**。最初一轮仅规划；用户随后授权逐项实施，并要求首先复用已有课表导出。当前批次只补本人理论课表读取，原 47 个工具保持兼容；公开馆藏等仍是后续计划。学校入口的协议证据见[调查索引](investigation/2026-10-23/README.md)，当前架构以[架构文档](architecture.md)为准。

## 1. 先做哪一批

按功能逐项验收：本人理论课表先衔接现有导出；随后公开馆藏，再推进已验证的一卡通、宿舍水电、网络账户及其他只读能力。每项只接入已证明的读取范围，不为菜单里的每个动作增加工具。邮箱先完成授权可行性验证。**wpay 按用户要求搁置、不接入**；研究生／医学院暂缓，`r` 和综测继续暂停。此前成功／失败证据保留原时间，优先级变化不改写历史。

| 拟新增工具 | 用户能做什么 | 配置及本批范围 |
| --- | --- | --- |
| `search_library_books(query, field="any", page=1)` | 按文字或 ISBN 找学校馆藏 | 无需账号；首版支持已有成功证据的 ANY／ISBN，不开放当前异常的 TITLE 查询 |
| `get_library_book(book_id)` | 看指定书目、分馆及馆藏状态 | 无需账号；固定公开协议，不读取借阅人、本人借阅或订购全文 |
| `get_academic_timetable(semester="")`（当前批次） | 看本人一个学期的周次、星期、节次及地点；同一响应返回真实学期选项 | 复用 JW 会话；理论课表输出直接兼容已有导出课程结构，校历及导出审阅继续用原 Skill |

馆藏名称和参数仍为拟定接口。课表当前源码新增一个查询工具及同核 CLI，不新增导出工具。旧 `get_schedule` 继续是 MySTU 短期日程，`get_courses` 继续是 MySTU／雨课堂课程；不借旧名称改变它们的含义。

选择这两项的原因是：公开馆藏不增加认证成本，课表复用现有学校账号；用户马上能获得有用信息，同时避免一开始并行引入学工多种协议、ehall 多个 OAuth 客户端及水电明文回调等不同复杂度。

## 2. 代码怎么保持小而清楚

沿用现有单向分层，不新建平台注册框架、配置 DSL、通用爬虫、自动探测路由或新的兼容门面。

| 层 | 职责与计划位置 |
| --- | --- |
| MCP／CLI | 工具和命令只验证参数、调用同一业务服务；不写学校字段解析、认证或重试循环 |
| 业务服务 | 组织一次搜索／详情／课表读取，统一返回数据、来源、核查时间和完整性；不复制网络与存储实现 |
| 来源访问 | 书目用 `features/library/adapter.py`；课表沿 `features/jw/adapter.py` 增加固定读取；只知道本来源的真实入口和协议 |
| 契约与解析 | `schema.py` 保存路径／字段合同，纯解析不联网；课表解析独立在 `features/jw/timetable.py`，不继续扩大成绩／考试解析器 |
| 共用设施 | 复用 `CampusHTTP`、`AppError`、JW Vault、退出／换号屏障、现有 CLI／设置页和能力目录；不把研究脚本搬进运行时 |

公开馆藏模块先保持 `schema/parser/adapter/service` 四个职责文件；只有出现实际需要才加模型，不为每个上游接口造一个类。`App`／`server` 只增加薄转发，不集中所有新业务流程。

### 必须处理的现有代码细节

1. **OPAC 的实际路线是匿名 HTTP 加 JSON POST。** 当前 `CampusHTTP.request` 只有 GET／表单 POST，现有传输规则也不允许 OPAC HTTP。需要给共享传输追加可选 JSON body，与表单 body 互斥，保留旧调用行为；仅允许 `library` 匿名访问固定 OPAC origin 及 `/init`、`/rest`、`/opac`、`/lcsbehavior`。适配层继续限制公开查询操作名，不将通用 `/lcsbehavior` 暴露为任意代理。不得借此扩大认证 HTTP、关闭 TLS 验证或携带学校登录态。
2. **只登记来源不等于接入完成。** 当前 `App.refresh` 的末尾分支会进入雨课堂采集；新增 `library` 后须明确要求通过带关键词的专用查询，不能误落旧分支。`App.status` 也须明确显示匿名来源。它们是本批的小范围组合修正，不重写所有来源调度。
3. **课表与成绩刷新独立。** 课表服务复用 `JwAdapter` 的登录状态、传输标记和 HTTP 生命周期，但不额外下载成绩／考试，也不改变它们既有的部分失败规则。读取前后核对 JW 会话指纹，在退出／切换账号后丢弃本次私人结果。
4. **第一批不新增持久缓存。** 按需查询直接返回结果，避免为首版引入新表、迁移和同步任务。当前 `Store` 是增量 UPSERT，`CourseSync` 只为 MySTU／雨课堂设计；把课表塞成 `course` 会留下已撤排课或混淆作业语义。以后确需缓存，再单独设计按账号／学期替换的完整快照；不在本批预建。

来源证据：[OPAC 实测](investigation/2026-10-23/library-round2.md#1-opac公开文字检索与二段读取已取得正向证据)、[JW 实测](investigation/2026-10-23/academic-network-round2.md)。代码边界见 [network.py](../src/stu_mcp/network.py)、[JW 适配器](../src/stu_mcp/features/jw/adapter.py)、[Store](../src/stu_mcp/store.py)、[现有同步](../src/stu_mcp/sync.py)。

## 3. 改版后如何避免静默返回错误

可靠性留在来源边界，Agent 不必知道网页的每个字段，也不靠 Agent 猜错误原因。

- OPAC 初始化参数取本次公开响应；检索 ID 与二段详情一一核对，区别 `CTRLNO`／`ctrlNo` 和字符串／布尔成功值。返回每页范围、总数及是否还有下一页；正总数却空行要报异常，不能变成“没有书”。书目成功、库存失败应明确显示两个结果。
- 课表的学期、隐藏字段和节次模式取当前表单。完整返回已排课与未排课项目，保留同课多个安排和未知值；不按网格容器数算课程数。字段歧义或无法解析的安排必须明确失败，不能跳过后自称完整。
- 请求总数、总时限、响应体积和分页都有边界；沿用错误类型与已验证的重试规则。POST 不自动重试，凭据／返回 HTML 不出现在错误文本。
- 返回结构区分 `source`、`checked_at`、`complete`／覆盖范围及部分失败；错误是否来自登录、权限、限流、网络或协议变化分别说明。首版直接读取失败不会伪装成缓存成功。

课表本批已通过当前学期非空与历史空学期的 CLI／MCP 真实读取，课程／教学班与安排按页面字段关联。当前样本仍有计划教师明细未匹配网格，因此返回部分结果与待核对项，未宣称学校全部安排已经完整。具体回执见[本批验收](verification/2026-10-23-academic-timetable.md)。没有在真人样本出现的单双周等情况用合成测试，不冒称已实测。

## 4. 邮箱如何接入而不变成完整邮件客户端

学校当前邮箱指向中国世纪互联 Outlook。已核对学校入口、DNS、公开租户发现及中国 Graph 的匿名 401；**本人 OAuth 和实际邮件读取尚未验证**，具体来源和权限见[邮箱调查](investigation/2026-10-23/campus-mail.md)。

实施前先解决这三个问题：

1. 项目使用哪个正式注册的中国云公共客户端，学校是否允许用户同意所需委托权限。面向普通人的目标是打开自己的浏览器／设备确认授权，不是让每位学生去注册 Azure 应用，也不借用 Outlook 官方客户端 ID。若项目无法提供适用的注册和授权方式，就不能承诺邮箱开箱即用。
2. 本机设置页采用授权码加 PKCE；无桌面 CLI 可采用 device code，由用户在自己的设备完成微软登录。两者调用同一邮箱认证核心，按学校真实策略处理 MFA／同意；不要求服务端浏览器，不把学校密码发送给 Agent。
3. 用实际本人账号验证列表／阅读／搜索、分页、失效与退出，确认中国云、租户、账号及权限关联。认证后的加密 token 与 JW、WebVPN 会话分开；学校账号配置成功不代表 Graph 已授权。

首版候选范围只保留“邮件检索／列表”和“指定邮件阅读”，暂不承诺发信、删信、规则、日历、联系人、全邮箱同步或后台推送。若只展示主题等基本属性，用 `Mail.ReadBasic`；若要读取正文，需 `Mail.Read`，不申请 `Mail.ReadWrite`、`Mail.Send` 或全租户应用权限。最终范围确定后再定两个工具的最小参数和授权，不预建办公套件框架。

微软当前官方文档列中国云支持消息列表／详情／附件／搜索，但消息 `delta` 不支持中国云，因此不能把全球版增量同步当作本项目实现基础。列表从小页按需读取，使用经过地址校验的 `@odata.nextLink` 和必要字段；邮件 HTML 只作不可信数据处理，不加载外部资源、执行脚本或自动标记已读。附件以后单独评估，无需首版同时实现 Graph 和 IMAP 两套协议。

## 5. 怎样验收和拆提交

| 独立交付 | 关键验收 |
| --- | --- |
| 共享传输最小补齐 | 旧表单请求兼容；JSON 编码与 body 互斥；仅固定匿名 OPAC HTTP 可读；认证状态、跨站和未知操作被拒；请求预算、跳转后丢 body、响应上限及 POST 不重试 |
| 公开馆藏 | 正常检索、两段 ID、分页／末页、零匹配、正总数空行、错误成功值、二段缺项／多项，以及库存部分失败；无需 keyring 或登录 |
| 本人理论课表 | 多段／多周安排、未排课、明确空态、表头换序／歧义、布局噪声、登录 HTML、当前表单字段、并发退出／换号；不触发成绩／考试查询 |
| 工具与说明 | CLI／MCP 共用服务；旧 47 工具签名和行为不变；设置页无需新输入；能力目录只宣告实际完成范围；来源和核查时间可见 |

自动化测试使用合成 HTML／JSON，不保存私人课表或邮件作为 fixture。实施完成后按仓库要求跑全量 pytest／Ruff，并另记真实校园读取验收，不能以离线测试代替它。

课表读取与现有[课表文件转换](timetable.md)继续分开：后续导出须另外核对最新校历、教学周起点、作息及调课证据，OA 仍默认不开启；不能由一次课表请求自动填 `latest_verified=true` 或 `complete=true`。复用已有转换核心和 Skill，不再写第二份生成器。

首轮只规划的记录保留在提交 `955b06c`。当前课表批次不添加依赖、登录入口、数据库或后台任务；其余拟定功能仍未注册。每批完成自己的测试与真实读取验收后，再将该批能力从“方案”转为“已接入”，推送与发布另行处理。
