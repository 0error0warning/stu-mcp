# 已知业务覆盖审计

**仍有协议缺口，不能以“全部入口已经分配报告”代替“全部业务已经读通”。**
本次审计将原入口目录、当天各分报告、主校50事项、医学院208事项和源码能力目录对齐为
[业务协议台账](business-protocol-ledger.csv)。只增文档，不实现 MCP，不新增认证白名单，
不改原 [620 URL 覆盖表](entry-coverage.csv)。本审计只读现存证据，没有向学校站点发送新请求。

## 口径及机器可查字段

- 原目录620个URL中176个被归为业务候选，包含别名、旧入口、静态页与失败入口；不是176个系统。
- 原目录153个数据库资源详情作为**引用集合**保存，不拆成153个业务系统或已验证订购授权。
- 源码纯目录有13个已实现业务组、16个导航/未接入项；`server.py` AST有47个工具。
  配置状态、代码实现和当前上游查询成功互不替代。WebVPN是访问通道，不另凑业务组。
- 台账单位是**明确的入口及业务范围**。同系统下公开检索与本人记录分行；不同系统不按主机名合并。
  一个已读列表的所有参数排列、厂商编译包后台路由不扩大为无限任务。
- `source_entry_rows`按原CSV的`source_row`关联；`entry_aliases`保存该组原URL。
  原620行均有明确映射，表示已归档的来源范围，**不是全部协议完成**。
  别名保留发布关系，不表示各协议/路径都可用、已经迁移或共享主入口的验证状态。
- `source_url`是发布来源，`evidence_doc/evidence_scope`是证据及限制；
  `request_method/contract_fields`区分真实读取与静态声明。
  `resolved_entry_url`另存本轮appShow实际发布/跟进的安全目标，未跟进的目标仍写明未查。
  `last_checked_at_utc`只记该范围已知请求时间；留空表示缺少可精确归属的请求时间。
  本地解析、报告写入和生成台账不更新联网时间。
- `existing_integration`单独记录源码现有支持；没有新查询证据的现有适配行可为`pending`，
  这不表示功能被删除。无远程入口的本地功能`entry_url`留空，不编造学校URL。

| `protocol_state` | 含义 |
| --- | --- |
| `pending` | 已知业务尚无具体成功读取合同，或仍缺当前证据 |
| `static_only` | 只有导航、表单、页面壳、脚本声明或公开事项元数据；未验证该行实际业务 |
| `read_verified` | 已有具体匿名请求、方法及结果字段/结构；仅限该行范围 |
| `auth_read_verified` | 已有该来源认证后的具体读取；身份绑定、字段语义等未完成项仍列明 |
| `access_blocked` | 本轮解析、连接、TLS、HTTP错误或明确本地访问约束阻碍读取；不表示永久停用 |
| `auth_blocked` | 实际认证链或受保护读取未完成；没有尝试登录的业务不一律标此状态 |
| `paused` | 用户明确暂缓的`r`及综测；保留历史证据，不继续请求 |
| `excluded_reference` | 来源/公开栏目/第三方资源/明确排除项，不冒充已验证业务 |

当前CSV有277个**范围行**，不是277个系统，状态分布如下。50事项办理边界、公开查询、
本人读取、历史别名及引用集合的粒度不同，不能用这些行数计算学校系统完成率。

| 状态 | 行数 | 状态 | 行数 |
| --- | ---: | --- | ---: |
| `read_verified` | 30 | `auth_read_verified` | 19 |
| `static_only` | 134 | `pending` | 18 |
| `access_blocked` | 48 | `auth_blocked` | 9 |
| `paused` | 3 | `excluded_reference` | 16 |

3个暂停行指向`r`和综测两个业务及其事项引用，不是第三个暂停系统。

## 补出的有限范围

一网通办公开目录五页、50详情、正常空页属于一个已验证的目录合同。
`matter_`开头50行记录**各事项实际办理边界**，不是50次申请已跑通：37项内部事项尚无
实际流程/本人记录合同，13项外部跳转也不自动取得目标会话。申请、审批、支付、改密、
验证码等本轮不执行，工作人员业务不伪装成认证故障。

医学院另保存[208事项安全明细](medical-service-matters.csv)，不是208个独立系统或208份
办理表已经查过。公开目录21页有208行、207个不同ID（244跨页重复）；再按官网真实
“网络与信息中心”部门筛选补回ID4，得到与同轮声明总数匹配的208个不同事项。
目录成功与每项实际申请权限分开；额外跳转只有在具体入口及用途证明后才列为独立业务，
CMS指引、文件下载和后台入口不自动变成学生查询能力。

旧学工门户原报告只概括“19个应用”，本地已保存的安全结构记录实际含19个明确卡片名和
appShow链接。其中基本信息、问卷、证明打印、宿舍违纪/卫生、困难生、助学金、绿色通道、
助学贷款、违纪处分、荣誉、第二课堂、学生社团等不能从“主机已有报告”推定完成。
台账逐入口保留；与50事项重叠的勤工/住宿精确目标复用已有行，同名新旧路径的关系仍待证。
另保留门户已发布的消息/公告链接。随后[学工补查](xg-completion.md)累计取得17个有效应用
配置、21模块脚本，并实际读取勤工3项、证明申请空列表、请假未销假对象及贷款申请空列表；
台账只升级这6个具体POST覆盖的范围。
其他模块有声明仍不等于读通；新`xsfwdt`目标与历史`xsfwnew`失败分开。
本审计只读取既有脱敏结构记录，没有自行重新查询个人数据。

其余已知范围完整列在CSV，包括网络账户与登记菜单、独立宿舍/水电、校园卡、各预约系统、
馆藏/本人借阅/空间/CARSI/CALIS、公开课程与本人学期课表、就业、仪器/资产、软件支持、
项目科研/人事/财务/采购、档案公文/会务、车队与门禁、校友/邮件/录取、医学院独立业务，
以及访问失败的历史教学/活动/媒体入口。没有仅截取十个重点，访问失败条目仍在台账。

水电历史数组当前结论为12个位置，2/3/4为JS空槽。此前9列是调查器过滤空槽的错误，
不是上游变更；剩余缺口是身份、金额/单位/分摊及范围语义，见
[水电补查](dorm-utilities-followup.md)。

## 能证明什么

旧`coverage_audit.py`的`remaining={}`和按主机匹配报告，只能说明目录项已经归属或排除，
不能证明认证、接口字段、分页或本人业务均已验证。新的台账明确保留静态、待查、受阻、
暂停和已验证的窄范围；公共查询成功也不将整站提升为完成。

该台账是**截至所列证据的已知业务范围**，不是学校所有未公开内部系统的穷尽证明。
后续发现官网新入口时新增具体行；只在该行对应请求和结果证明出现后升级状态，
保留旧时间、受阻原因、读写界限及独立来源身份。可直接筛选`missing_evidence`安排补查，
无需扫描或登录任何不明主机。

本次仅做文档校验：CSV ID唯一、8种状态、UTC格式、方法/字段证据、文件链接、原620行
一次性映射、主校50事项与医学院208唯一事项、认证参数/fragment递归清理、13已实现组及
47工具源码计数。原620覆盖表和50事项表与HEAD一致；没有为文档修改重复运行产品全量测试。
