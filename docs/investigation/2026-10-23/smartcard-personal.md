- 本轮新建来源隔离的临时 cookie jar，读取当前图片验证码并正常填写，单次登录 POST 成功；没有省略、绕过、爆破验证码或尝试他人账号。没有启动浏览器。

- 没有打开或调用挂失、解挂、改密、充值、限额修改、捡获卡名单、发消息或写入接口；查询类型选项中的这些名称只是历史记录分类。

## 多步查询、续行与表格合同

历史查询的正常路径：

1. GET 入口，表单提供本人卡账户 `account` 与交易分类 `inputObject`。本轮账号选项只有 1 个；必须使用该已登录页面提供的账户，不能把输入学号直接当成内部卡账户编号。
2. POST 原表单 action（含来源自己的 `__continue`），返回日期表单。
3. 日期为 `inputStartDate` / `inputEndDate`，格式 `yyyyMMdd`。页面提供三天、一周、一月等快捷项，并校验单次不超过 30 天。
4. POST 日期后可能返回“操作正进行”页；页面明确在 1 秒后提交当前 `form1`。本轮等待对应间隔，再向该页的原 action 空 POST，一轮续行即获得结果。
5. `__continue` 必须来自当前响应且仅在内存保留。相对 action 可能只有查询串，须相对于当前页面 URL 解析；不能拼回站点根路径，不能记录参数值。

统计采用同类续行，但日期粒度为 `yyyyMM`，并非历史查询的八位日期。它按交易类型和月份生成图表；本轮使用同一个月，未测试跨度极限。

续行是上游只读查询协议的一步，不是重试登录、重新发起交易或无限轮询。未来实现应给整个链路设置请求/时间上限，只有观察到既定“进行中”页才按页面节奏续行，登录页、错误页和结构变化均不能归为空数据。

## 接入边界

已经实证无需浏览器即可完成当前本人认证、余额、充值记录、流水空态及统计图请求。验证码仍是正常认证步骤；它可以作为设置页/CLI 的短期图片挑战，不能藏成 MCP 的“无条件自动登录”。不引入破解服务、外部模型依赖或验证码绕过。

今后实现可围绕“卡概况”和“按日期/类别查本人流水”复用同一独立认证会话与轻量 HTTP adapter；当日、历史与统计保留各自合同。先不把完整个人资料、操作员信息、写操作和图像统计扩张成大量工具。统计数值、分页、会话过期、多个卡账户、查询密码错误与图片验证码错误的具体响应还需独立验证，不能从本次单账号成功推定。
