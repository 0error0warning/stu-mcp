# DSH 原生薄插件验收

日期：2026-10-28。DSH：Windows Desktop `0.2.1-rc.3`。
STU MCP：`0.7.3`。薄插件：本地 `dsh-stu-mcp@0.1.0`，未发布。

## 实现范围

`integrations/dsh` 是可选 UI 包；继续复用已配置的官方 MCP 桥接和同一 Python 业务核心。
既有 stdio / HTTP / CLI、工具参数与登录流程没有被这个插件改写。
它仅提供两个固定界面操作：状态读取和打开共用设置。没有任意工具执行端点。
不在 UI 中收集学校凭据，也不传递私密设置 URL。

## 本机证据

- 使用桌面随附 CLI 的 `plugin --profile desktop add <本地目录>` 安装。
  安装前备份 profile 清单、patch 与已有 lock 文件，未更改模型配置。
- 插件页刷新后，“已安装插件”出现 `dsh-stu-mcp`，详情版本 `0.1.0`，组件 `stu-mcp-panel` 显示运行中。
- 左侧出现 STU MCP 入口；对话右侧显示 STU MCP 标签及实际状态。
- 状态调用返回 **52 个工具、STU MCP 0.7.3**，配置目录来自 MCP。
  学校账号待配置、对分易尚未启动等事实与当前共用能力目录一致。
- 点击“打开共用设置”，返回 `settings_opened` 的成功说明；系统浏览器出现“STU MCP 设置”窗口。
  没有输入真实凭据或进行学校登录。
- 管理页停用后，组件显示“已关闭”；当前窗口可能保留已加载的客户端界面。
  退出并重开 DSH 后，左侧入口消失，原右侧标签保留布局位置并显示“这类内容还没有可用的查看方式”。
  这是宿主的持久化标签行为，不把它记成标签已被删除。重新启用后左侧入口恢复，
  点击后状态再次成功显示 52 个工具与 0.7.3；最终保留在这个可用面板。

## 边界

这是本机安装，不代表 npm 或 DSH 公共插件市场已有条目。
配置状态不代表学校业务当前可读；真人登录、个人数据和其他 DSH 版本未在本轮验收。
可选界面的安装与 MCP 连接分开管理；移除 UI 不删除 MCP 配置或共享凭据。
