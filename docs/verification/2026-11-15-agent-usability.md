## 已修正的问题

| 原有行为 | 现在的行为 |
| --- | --- |
| 列表缓存的通知返回成功，agent 容易以为已取得正文 | 明确 `metadata_only` / `content_ready` / `detail_available`，返回来源对应的 `next_call` |
| 通知搜索可能一次返回大量已缓存正文 | 返回1200字符预览和详情调用；正文默认8000字符分页，续页读完整缓存 |
| 附件列表未取回、已知空列表和越界都提示重新刷新 | 分别为 `attachment_not_cached`、`no_attachments`、`invalid_attachment_index`，只在需要时补详情 |
| 不支持的格式只有错误；无文字 PDF 可能成功返回空文本；HTML 下载页可能被当成附件文字 | 返回未读状态、经过校验的通知正文链接及 `show_source_link`，保持私人读取的会话版本检查 |
| 公众号的人工处理描述缺少统一的用户交接动作 | 已识别的验证码、失效、正文不足返回 `show_source_link` 和原文入口 |
| 完整功能状态包含大量重复信息，已知单一来源也只能全量读取 | 增加来源视图和 `compact`；默认完整返回兼容 |
| 多种空查询只说没匹配，缺少是否已刷新的依据 | 补 `query_scope`、`empty_reason` 和有需要的刷新调用；多来源查询优先使用免登录或已配置来源，不强求补齐其他账号 |
| 多处分页只有 `has_more`；扫描受限时总数易被当成完整统计 | 补 `next_offset` 和总数下界标志，查询/成绩统计标明部分结果 |
| 只更新兴趣时，工具将其他资料用默认空值覆盖 | 只传实际修改字段；清空需要 `clear_fields`，冲突值会拒绝 |
| 远程缺登录仍指向客户端无法使用的本地设置流程；升级后的重启动作不区分 transport | 给本人宿主命令，OA 对应 WebVPN；stdio 重载、HTTP 重启宿主服务 |
| 外卖歧义提示使用“返回的分类”，实际上没有分类 | 真正返回分类和区域选项；缺平台餐段分类时给同区域的有界继续调用 |
| 固定来源、后端、状态等选项只写在文字说明 | 工具 Schema 增加机器可读枚举，应用的既有结构化参数错误保持兼容 |

新增纯响应辅助模块 `agent_guidance.py` 和通知 `presentation.py`，避免在工具描述里堆叠业务判断。没有增加模型调用、认证输入、隐藏联网或自动重试。同步 CLI、随包 `stu-campus` 技能和[使用约定](../agent-usage.md)。
