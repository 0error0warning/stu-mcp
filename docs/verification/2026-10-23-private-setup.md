# 本人浏览器中的 HTTP 配置交互（2026-10-23，未发布）

本轮在 `0bc3b74` 上继续修正开源 stu-mcp 的首次配置体验：HTTP 优先不等于 CLI-only。上一轮[能力目录记录](2026-10-23-configuration-catalog.md)中的“网页只返回固定 CLI 命令”是当时实现，本轮已替换。仍未发布新版本，现有 v0.6.2 发行附件保持原样。

## 复用与替换

复用原来的 HTTP 来源协议、正向身份／业务证明、Vault 加密保存、账号关联和退出代次屏障。CLI 仍要求真实 TTY，保留全部原命令。显式传入网页交互时，由共用核心请求输入或显示挑战，不模拟终端，也不启动自动化浏览器。

`setup_auth` 提供有界的内存交互桥：同一时间一个认证任务，默认 300 秒期限，最多两项近期任务历史；账号、动态码、二维码和原微信回调只通过私密设置 API。每个输入挑战只能消费一次，完成、取消和过期均清理输入及二维码。结果只输出已知安全状态，不反射适配器任意文字、证明、账号、Cookie 或回调。

`setup_web` 继续绑定回环并校验精确 Host、Origin 和页面专用请求头，不开放 CORS，不记录请求正文。输入有大小和读取超时限制，拒绝重复长度和分块请求。二维码由原有 qrcode 依赖生成 SVG 数据图，只供本人的私密页面；没有新增网页框架、二维码服务、Pillow 或生产浏览器依赖。

本机 `open_setup` 自动打开系统浏览器；CLI 和页面均为可选入口，不依赖 Skill。带访问能力的设置地址不进入 MCP 返回，不能以远程 MCP Bearer 代替页面令牌。无桌面服务器继续完整使用 CLI，私有转发属于单独选择，不放宽设置页边界。

## 页面与状态

页面沿用原配色与列表布局，主区域只有学校账号、雨课堂、对分易、WebVPN 四行和一个当前配置工作区。按步骤显示实际需要的表单、官方二维码或原授权回调；普通学校密码不保存，WebVPN 自动重登单独启用。教务的 HTTP 回调仍需本人选择，网页只授权本次，不写持久兼容设置。

配置后逐项显示业务结果；部分失败不丢弃已成功的独立会话。本地保存状态不冒充当前学校业务可读。设置页与 MCP 复用被动对分易状态和相同能力目录，读取状态不启动 worker；登录沿用原回调和唯一控制对象，不创建新监听计划。入口清单和未接入功能折叠展示，不要求用户理解内部来源关系。

取消在协议检查点及最终保存 guard 生效，不撤销已完成的会话或既有授权计划。显式取消或关闭设置服务会清理待处理输入；浏览器关页只尝试发送取消请求，未送达时由任务有效期兜底。已经发出的同步网络请求可能在原有界超时后退出，此间保持单任务约束；对分易回调发送后取消不能撤回，结果未知时只读核查，不重复发送。

## 发现的问题与修复

首轮完整回归为 2209 项通过、4 项跳过、1 项失败，失败是 Windows 两个线程首次使用同一空锁文件时，在取得系统锁之前初始化文件导致 `PermissionError`。已改为先取得原生锁，再初始化文件；保留路径安全检查、限时、互斥及异常释放规则。新增原生并发回归，锁与整组 WebVPN 自动重登 47 项通过，原失败用例和三项锁回归单独重跑均通过。

隔离安装最初两次在 stdio 的 `initialize` 超过原 12 秒检查限时：一次已通过前七种客户端后超时，另一次在第一种配置超时。各配置实际使用相同启动参数。单独诊断的两次初始化分别为 10.72 秒成功及 14.16 秒超时，子进程第 8 秒线程栈均仍在导入 MCP SDK 的 Starlette／uvicorn 依赖，没有进入设置页认证。检查器因此单独给予首次初始化 30 秒，初始化后的整组工具查询仍限时 12 秒，保留外层总预算和至多 4000 字符的合成环境失败日志；未修改产品超时或跳过客户端检查。
