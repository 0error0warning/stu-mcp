## 既有实现与遗漏

原 School Hub 的 `school_hub/scrapers/jw.py:JwScraper.login` 自初始提交 `df97d2f` 已有 requests CAS 登录：
GET SSO → 提取 `lt/execution/_eventId` → POST 账号密码 → 跟随教务回调。
此前没有完整查到这份实现，应当作为协议验证的起点。
但它只以最终 URL 包含教务域名判成功，使用 HTTP service、默认环境代理及自动跟随重定向，不能直接作为成熟适配器或已验收依据。

既有教务、MySTU 和报修记录分别来自人工／无头浏览器首登，再以 HTTP 读取业务或浏览器上下文操作；
没有找到纯 HTTP 首次认证完成的正向验收回执。原代码存在与真实成功证据必须分开。

### CAS

本轮实际获取的官方来源为 `https://sso.stu.edu.cn/login`、其 `/js/ad.js`、`/js/notice.js` 及表单内联 `doSubmit`；
业务入口为 `https://my.stu.edu.cn/discussion/my-courses`、`https://repair.stu.edu.cn/`、
`https://jw.stu.edu.cn/jwglxt/xtgl/login_slogin.html`。
当前表单动态字段可由 HTTP 获取；密码仍必须只发到验证过的学校 HTTPS SSO。
教务 HTTP 回调属于独立的传输兼容选择，不能因为是在做实验就默认接受。

已经准备单次本人终端实验：隐藏输入，不接受参数／管道／环境变量凭据；每来源使用新 client，
只允许固定学校 HTTPS 主机，一次 POST，任何失败／未知／挑战都停止后续账号提交。
只保存脱敏结果，不保存 Cookie、票据、账号、密码或页面原文，不写产品会话或缓存，不提交报修。
单请求采用阶段超时，另检查总预算；阶段超时不冒充严格的进程墙钟截止。
实验防护经合成 transport 验证，包括 POST 回执未知不重发／不继续下一来源及输出脱敏；这不算真实认证。
**真实账号实验仍等待本人终端输入，尚未执行。**

`/por/login_psw.csp?anti_replay=1&encrypt=1&apiversion=1`；TOTP 为 `/auth/token?apiversion=1`。
这些是前端契约调查，**两个认证 POST 都未发送**。
即使 `ErrorCode=1`，存在 `NextService` 时仍需继续认证；不得只看初始化码、会话标识或门户跳转。
是否可替换现有无头 Chromium，仍需真实账号完整跑通并读取受保护 HTTPS OA 后决定。

## 当前设计结论

按以下顺序验证和选择实现：纯 HTTP → 确有需要时无头浏览器 → 实际出现人工步骤时提供对应交互。
先保留现有可用功能和 38 项工具，不把匿名协议调查直接发布成已完成的登录适配器。
分别验证首次登录、业务读取、失效恢复、账号切换和异常停止；网站页面变化时也按这些证据退化，不能猜测“学校强制桌面”。
