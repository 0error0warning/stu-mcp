# 2026-11-15 本机 v0.7.7 与 DSH 0.2.2-rc.3 验证

本轮按用户要求安装官方 v0.7.7、接入本机 DeepSeek Harness，并通过实际模型调用检查工具流程。验证观察的是可见工具名、参数、返回状态、公开进度说明和最终回答，没有展开或保存隐藏推理内容。验证记录不包含 API 密钥、账密或非目标窗口画面。

## 安装与接入

原 DSH 配置指向开发仓库的 `.venv`，默认 uv 工具目录中没有独立 STU MCP 安装。现安装官方 v0.7.7 wheel，`stu-mcp`、`stu`、`stu-checkin` 三个入口由 uv 管理；核心仍为正式发行包，没有把后续源码提示补丁覆盖到已安装 v0.7.7。

`stu-mcp verify` 完成 initialize、tools/list、get_capabilities，返回0.7.7和53项工具。`connect dsh --apply` 在私有数据目录生成备份，保留原 profile 其他配置，更新为 uv 安装中的绝对 Python 路径。当前 DSH 实际 MCP 子进程也使用该解释器，未继续依赖开发 `.venv`。被动状态为签到服务未启动，本轮没有启动或停止后台计划。

实际安装的 DSH 为 **0.2.2-rc.3**。使用该宿主的真实 Cordis、ToolRuntime 与 MCP 桥接，执行 `check_dsh_runtime.cjs`：发现53项工具、版本0.7.7，状态调用、缺登录、无效来源、空缓存和释放后重连通过。`check_dsh_panel.cjs` 的固定操作、公共字段投影、错误脱敏、取消与 Remote 标记检查通过。

## 薄插件兼容修正

发布版 `dsh-stu-mcp@0.1.0` 的 `engines.dsh` 精确要求0.2.1-rc.3，安装到当前宿主被正常拒绝。根据新宿主上的真实桥接与插件边界测试，将本地源码版本调整为 **0.1.1**，仅明确允许0.2.1-rc.3或0.2.2-rc.3，并同步两个宿主 peer 的同一范围。没有开启版本风险豁免，没有改写 v0.7.7 的发行附件。

以 `npm pack --ignore-scripts --offline` 构建5文件安装包，保存在应用私有数据目录的 `artifacts/dsh-stu-mcp-0.1.1.tgz`，通过同一 DSH 桌面附带 CLI 安装。当前依赖为该持久化 tarball，模块解析落在 DSH profile 的 node_modules 内；不再是开发目录链接。安装包 SHA-256：`f81e5f91ffadb9c65603be58f790e69eb82344b7d2249d56e2e319d4ffb1deb1`。

DSH 侧栏实际显示“已连接”，展开连接信息后显示“版本0.7.7 · 53个工具”。本机0.1.1兼容包尚未发布；已发布 v0.7.7 内仍是0.1.0。

### 迁移中发现的目录链接问题

首次直接 add 新 tarball 后，manifest 已变成 file 引用，但 lockfile 和模块解析仍指向旧开发目录。移除旧依赖再添加持久化 tarball 后，依赖与模块位置恢复一致。

这次 Windows 包管理器操作也清除了链接目标里的5个插件源文件。已从操作前生成的完整0.1.1归档逐个恢复，未用整仓库 reset；Git 确认三个实现文件与原提交相同，只保留预期 package.json 与 README 改动。profile 的 package.json、pnpm-lock.yaml、patch 另有私有备份。后续迁移应先备份目录链接的目标源码，并核对最终解析位置；不能仅凭 add 成功断言已脱离开发目录。

## 实际 DeepSeek 模型调用

使用桌面端当前已配置的 **DeepSeek-V4.1-Flash，Max**，在新会话进行两轮；两次均限定 STU MCP 公开信息和不修改项目文件。没有进行新登录或读取个人成绩、课表等业务。

| 场景 | 可见结果 |
| --- | --- |
| 查校团委“攀登计划”最近通知及正文 | 模型检查缓存时间、刷新公开来源、检索项目同义表述并读正文；找到2026-11-02的2027年项目申报通知，给出标题、日期、内容及原文。没有停在独立栏目中2025年的旧记录 |
| 整理《汕头大学大学生创新创业竞赛激励办法》的奖励标准/申报条件 | 模型定位办法及配套细则，分别读取正文和附件；最终明确附件受验证码保护、未读到条款，返回两条通知正文链接，没有编造金额或条件 |

第二轮可见工具轨迹逐行统计：15次 search_notices、2次 get_notice、2次 read_attachment、1次 refresh_source，共20次 MCP 调用。最后一次附件读取后又有13次调用，包括刷新 OA 和多次检索/缓存分页；不是把 UI 的子单元格重复计数。DSH 另显示两轮合计16个生成步骤，这不是 MCP 调用总数。

## 从实测补充的源码指引（未发布）

有两处仍不顺手：收到 `show_source_link` 后继续跨来源找全文；以及无证据地提示公开校团委链接需要校园网/WebVPN。为此在共同核心和随包技能中补充：

- 附件链接交接增加 `handoff_required=true`，说明这是该附件自动读取分支的终态；立即交付标题、原文链接及简短未读说明。用户另行明确要求替代公开版本时再检索，不自动刷新 OA、遍历缓存或索要上传文件。
- `public` 通知详情/交接返回来源访问元数据：`login_required=false`、`user_network_checked=false`。区分公开来源和用户网络未知，避免从学校域名猜测必须校园网或 WebVPN；OA 不继承这一公开访问标记。

本机正式核心仍为0.7.7。上述源码补丁未发布、未热改安装包，本阶段只有工具轨迹和协议回归。用户随后明确要求读取 DeepSeek 思考日志，追加的隔离 headless 模型对照、交接说明修正及参数边界改动见[思考日志复测](2026-11-15-dsh-thinking-study.md)；不将后续结果混作此前桌面阶段已完成的验证。
