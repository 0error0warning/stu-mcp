# 纯 HTTP 首次登录真实验证 · 2026-10-21

本轮在用户明确授权后，用本人提供的认证输入和本人手机扫码，从全新 HTTP 会话验证登录及业务读取。
认证请求全部由 HTTP 客户端执行，没有启动 Playwright、执行学校登录页面 JS 或读取原浏览器登录态。
雨课堂二维码仅显示于本机终端，由本人手机授权；没有在浏览器中完成登录。
账号、密码、票据、二维码原料、会话 Cookie 和认证响应值不写入脚本、产品配置或验证回执；下文仅保留结构、状态和汇总数量。

这是对[匿名前置调查](2026-10-21-http-auth.md)的后续证据，不能用来改写此前“尚未执行真实认证”的历史事实。
也不是已经将这些实验适配器接入产品：当前正式登录入口、默认实现和 38 项 MCP 工具均未改动。

## 关键协议与实现发现

### CAS 与来源边界

- 当前 CAS 页面动态字段可由 HTTP 获取，密码只发学校 HTTPS SSO；三个依赖来源各自使用全新会话进行验证。
- MySTU 的真实成功响应为身份资料对象，含 `id`、`username` 等键。实验只记录键名及身份匹配布尔，不保存资料值。
  产品原 `proof` 仅排除明确 False 的薄弱点仍存在，但现在已有可用于收紧判断的实际正证据。
- 教务不能只看 SSO 发票据：还需要保留教务自身的预登录 Cookie／路由上下文，完成新旧系统登录衔接，再读取真实学生主页。
  SSO 与教务分用 Cookie jar；不把 SSO Cookie 或凭据带到 HTTP。成绩始终查询固定 HTTPS 地址。
- 报修空列表可能不生成工单表格，不能因此否定认证。确认本人列表标题、真实输入控件、默认筛选及表外明确空态，才可确认零条；未知结构仍停止。

### 雨课堂的实际字段扩展

真实扫码结果除关键 `UserID/Auth` 外，还返回 `Name/Nickname/Avatar`。官网流程只使用下一步所需字段，
实验初版却把这些正常附加字段当作异常，导致前两次停在等待结果之后，未继续交换和业务证明。
第一次只记录了未知结构，第二次补字段结构后定位了原因；两次失败记录保留，不能追认为完整登录成功。

最终实验按官网逻辑校验关键字段、冲突别名、类型、成功标记及真实课程响应；忽略未使用的元数据值。
不以整份对象的精确键集合代替认证判据，也不因新增无关字段放弃正常流程。
`success`、账号绑定、错误码和课程结构仍必须正向验证，空对象／畸形课程行／冲突身份不能冒充成功。

### WebVPN 未通过的准确含义

首次实验只记录了拒绝分类，丢失具体数字码，不能补记其原因。之后修正了一个明确的实验判别遗漏：
官方把 `20021` 归一为成功候选，再按 `NextService` 继续；候选仍需业务证明，不能跳过后续认证。
修正后的受控实验仍被拒绝，取得数字码 `20113`。本轮各次密码 POST 均至多发送一次，未提交 TOTP、未绑定令牌。

官方来源：

- [错误码常量](https://webvpn.stu.edu.cn/portal/jssdk/common/errcode.js)：20113 对应 `ERRCODE_EAUTH_FORBID_CLIENT`。
- [官方提示映射](https://webvpn.stu.edu.cn/portal/common/map.js)：对应“服务端禁止接入”。

已核对密码字段、nonce、公钥指数、普通网页请求与 Cookie 传播，未发现其他已证实遗漏；
官方 `rsa.js` 的三组合成向量与 Python 实现对照通过，但这些不能替代真实认证。
SDK 将实验 User-Agent 和 Chrome User-Agent 都识别为网页客户端，两种匿名初始化的公开策略开关一致；
这既不能确认，也不能排除认证阶段的终端／账号策略。不继续猜密码、绑定令牌或尝试绕过接入限制。

## 失败、修正与验证范围

实验过程保留以下问题，不只报告最终成功：

1. 初次本人终端输入未取得 CAS 重定向；之后用户明确提供本轮认证输入，直接测试取得服务票据。
2. MySTU 初次课程 GET 返回 500。实验漏了产品已有的 AJAX／Referer 请求头，补齐后相同固定 API 返回 200，课程解析通过。
3. 报修初版误把缺表头视为失败；按既有明确空态契约核对后通过。合成检查确认伪控件、表格自身空文案、缺空态及密码表单均拒绝。
4. 教务 HTTPS service 变体发票据后回调 500，未通过学生主页；本人确认 HTTP 回调后，继续核清预登录上下文和登录衔接，才完成实际成绩 proof。
   调查每次使用新的 CAS 票据，未重用前次失败实验的票据；学校正常重定向按 Location 跟随，每次实验不重复认证 POST。
5. 雨课堂两次因实验的过严对象结构判据停止；补诊断并只验证关键契约后，新挑战完成本人授权和课程读取。

实验脚本的合成防护检查包括：不在未知结果后继续后续账号提交、认证 POST 不重发、明确空态与伪控件区分、关键别名冲突拒绝、
忽略无关资料元数据、课程成功标记和逐行结构检查、结果脱敏。雨课堂 14 种离线场景及只读回环显示权限检查通过；相关 Ruff 通过。
这些只验证实验代码防护，不作为上表真实认证成功的替代证据。

本轮只改验证记录及实验脚本，没有改产品认证默认值、写入产品登录态／缓存、重跑学校业务提交或发布新版本。
未做 Docker、Tailscale 跨机、账号切换、自然会话到期恢复或多账号覆盖；当前账号一次成功不能保证学校以后不增加人工挑战。

脱敏逐步回执与脚本保留在工作区 `output/http-auth-review/`，受 Git 忽略，不包含在安装包；
其中 CAS、教务、雨课堂及 WebVPN 回执分别记录本轮的阶段、时间与结果。历史匿名调查及失败记录保留原样。

## 对后续架构的约束

真实结果支持优先建设共用的 CAS HTTP 认证底层、来源独立的会话与业务 proof，以及单独的雨课堂 HTTP 扫码适配。
WebVPN 保留现有无头路径，并把本轮接入策略拒绝作为未解决问题；不能宣称已有浏览器路线也经过本轮对照验收。
桌面交互是可选适配方式，不能因为当前代码写了 `headless=False` 就把它提升为学校部署前提。
切换产品实现前仍应补会话保存、退出屏障、失效恢复、取消和兼容验证；维持现有工具接口及逐来源故障隔离。
