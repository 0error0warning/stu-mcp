# 配置引导、能力目录与统一账号编排（2026-10-23，未发布）

本轮在 `codex/campus-entry-inventory` 的 `0fc4901` 基础上实现配置与功能映射。针对开源 STU MCP，不修改 Hermes 私有 `school_hub`、原 School Hub checkout 或用户已安装的 MCP。包版本暂保留 0.6.2，开发构建不是重新发布的 v0.6.2；官方已发布 wheel 不含本轮增量。

## 实现范围

- `capability_catalog` 维护 7 个配置组、13 个已适配服务范围和 16 个导航／未接入业务，引用原来的 47 项工具。
  `profiles` 展示配置后对应的功能，`services` 展示精确业务、入口、认证关系、接入程度与证据范围。
  学校入口与用途证据保留 2026-10-22 等原日期，不冒充本轮在线核验。
- `App.status()`、`HostRuntime.capabilities()` 和设置页复用此目录；旧字段保留，宿主复用一次被动对分易状态读取。
  目录不登录、不读取学校业务、不做网络探测或启动 worker；`SOURCES`、认证和网络请求白名单不随目录扩张。
  `session_saved`、历史刷新和本地 worker 状态与当前业务可读性分开，当前访问明确 `not_checked`。
- `login school` 一次终端输入，仅在内存复用普通学校凭据，为 `jw/mystu/repair` 分别调用原 HTTP 适配器。
  各业务独立 CAS、业务 Cookie jar、正向证明和加密会话，不建立中央共享 Cookie 或密码库。
  `--services` 选择业务；已保存同账号仅本地跳过，`--reauthenticate` 强制重新证明；旧单业务命令保留。
  教务 HTTP 回调仍仅接受本次明确选择或本人原有兼容设置，不扩展为 OA 或其他业务的 HTTP 许可。
- 网络／契约等来源错误按业务报告；拒绝、人工挑战、未知密码发送结果、身份冲突或退出代次改变停止后续共享密码认证。
  输入前记录全部所选业务代次，保存后核对本次密文回执，最后再核对整组；不会把并发退出后同账号的新会话采纳成本次保存。
  最终组校验即使没有具体 `source` 也返回未完成与错误，不能声称全部成功。
- 设置页按配置分组，列出对应业务名称、会话状态和未接入项；学校组只返回固定宿主 CLI 命令。
  没有新增学校密码网页／MCP 输入，保留 Host、Origin、私密 URL、CSP 与可选 WebVPN 配置保护。

## 验证与边界

自动测试使用合成账号、临时密钥库和回环服务，不读取或发送用户学校凭据。核心验证包括部分成功、旧会话迁移、同账号跳过、强制重登、并发退出／换账号、保存后竞态、最终组核对失败，以及无 TTY／存储失败先于输入。

设置页沿用项目开发用 Playwright，检查真实回环 API、固定命令指引、凭据字段拒绝、旧高级管理行为及本地保存状态不冒充在线成功。另人工查看桌面、390px 窄屏及 16 项接入缺口截图；没有横向溢出、页面脚本错误或外部请求。截图只使用临时空配置，保留在忽略目录 `output/playwright/school-config-2026-10-23/`，不进入发行包。

隔离安装检查从本次 wheel 创建一次性 uv 工具环境，核心没有 Playwright；以真实 SDK 调用 stdio 和私有 Streamable HTTP，核对 47 项工具名称、输入／输出 schema 和注解、能力目录及安装版 CLI 的 TTY 拒绝。另复核客户端导出命令、技能资源与合成课表转换、独立对分易 worker 的启动／存活／清理；不连接学校或提交真实业务。
