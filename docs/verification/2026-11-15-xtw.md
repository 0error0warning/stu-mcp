## 后续修正：附件验证码时返回通知正文链接

用户明确选择遇到附件验证码时，由 agent 把通知正文链接发给用户自行查看。当前保留 `status=interaction_required`、`ok=false` 和 `retryable=false`，并返回 `source_url`（通知正文地址）、`title`（通知标题）、`name`（附件名称）、`content_ready=false`、`next_action=show_source_link` 和内容信任标记。原通知正文和附件列表保留；不新增验证码输入、等待或续读会话。

`read_attachment` 的 MCP 工具说明明确要求 agent 将 `title` 与 `source_url` 组成可点击的通知正文链接交给用户。链接沿用公开来源 URL 校验，验证码页本身或带认证字段的缓存地址不会作为正文入口导出。CLI 对未读到附件的结果仍退出为 1。

原生 stdio MCP 实际调用制度 PDF 的 `read_attachment`，确认返回 `source_url=https://xtw.stu.edu.cn/info/1073/28651.htm`、通知标题、附件名称以及 `next_action=show_source_link`；`ok=false`、`content_ready=false`、`retryable=false`，原缓存通知完整保留。检查了 MCP 工具说明中的正文链接交接要求。回执单独保存为 `output/xtw-verification-20261115/mcp-captcha-source-link.json`，前述初版回执保留其历史语义。
