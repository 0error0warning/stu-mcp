# 默认 HTTP 认证与 CLI 实现验收 · 2026-10-21

本轮在 `codex/remote-hosting` 实现正式 HTTP 认证与报修适配器，并以真实学校响应验证。它替代此前“浏览器默认、无头尚未接入”的开发状态，不改变已发布 v0.5.0、main 或 Hermes 私有 `school_hub`。没有推送、发版或部署。

## 实现与边界

- `auth_http/transport` 统一直连、TLS 校验、主机白名单、请求/响应/时间预算及私密日志；CAS、雨课堂、WebVPN 各自负责协议和正向证明。认证不使用环境代理，不重试密码、动态码或一次性交换。
- CLI 默认调用 HTTP 编排，保存前核对来源版本并加密写入 Vault。退出、换账号或在途认证结果不明时，不覆盖新会话或误清其他来源缓存。认证输入只在本人终端，不新增密码或 token 参数。
- MySTU 仅传递学校实际需要的 `_UT_`，收窄到精确 HTTPS 业务域。CAS TGT 和 SSO host-only cookie 不混入业务 jar。ELC 和 Campus Moodle 分别初始化、证明和报告，不能因其中一个失败就丢弃已核对的 MySTU 身份和课程。
- 报修将独立 SSO jar 随本来源加密保存。页面 GET 可按固定目标获取新票据；列表、表单和经过 ID 校验的详情彼此不能替换。正式 POST 不跟随认证跳转，不重复发送。
- 报修仍为“实际完整预览 → 本轮本人确认 → 单次 POST → 新列表记录与完整详情核对”。CLI `--submit` 还要求真实终端输入“确认提交”；默认演练在预览后结束。
- Playwright 移至可选 `browser` extra，兼容登录必须显式选择。默认 Docker 不安装 Chromium 或桌面。雨课堂的可选题目 PNG 渲染仍可使用离线浏览器；HTTP 认证、活动和题目结构读取不依赖它。
- 对分易沿用原微信回调及同一个 worker，不替换为官网扫码，也不新增监听计划。

## 真实学校验证

环境为 Windows、Python 3.12.13。使用隔离数据目录和外置密钥文件，不修改用户现有运行配置。实际学校账号及令牌仅由本次明确授权的本地来源在进程内使用；没有把它们加入代码、命令参数、报告或公开 fixture。

对分易原回调的 CLI、真实回环后台、一次交换及“不新建监听”由合成测试覆盖。本轮没有重新获取真实微信一次性回调或执行课堂签到，不能称为新的真人登录/签到验收。

## 实测推动的修正

这些问题属于适配器差异，不能归因为学校要求桌面：

- MySTU 的最小业务 Cookie 桥接、Moodle `testsession`、有无末尾斜杠及 Campus 个人页跳转；普通身份有效和单个 Moodle 初始化失败分开处理。
- 报修 `default.aspx → student.aspx` 二级 CAS，以及每页独立取票据；不能重复读取无票据入口再把已验证登录误报失败。
- MySTU 库存中的已知旧 ELC HTTP 课程链接只升级到相同 HTTPS 官方路径，不开放认证 HTTP；Moodle 内嵌 `modtype_label` 不作为独立活动或重复链接。
- OA 的完整模板文章路径、表头 NBSP 空白、专属正文容器，以及 `accessory0` 附件字段。保留旧格式、唯一标识和拒绝歧义规则。
- HTTP 表单遵守 readonly、继承的 fieldset disabled 和 optgroup 禁用规则，不能构造浏览器原生表单不会发送的业务字段。

## 自动化与发行检查

自动测试只用合成账号/页面、临时存储、公开 TOTP 向量和回环服务；真实学校请求与合成测试分开执行。

最终完整回归 **1912 passed, 4 skipped**，199.47 秒。Ruff、wheel/sdist 构建、技能 UTF-8 校验、改动文档本地链接和补丁空白检查均通过。公开差异及新增文件共 71 个的私密值检查未匹配本次授权使用的真实凭据、会话值或联系人信息。

最终核心 wheel 验收时间为 09:48:09–09:48:23 UTC。13 个关键安装文件与冻结源码 SHA 一致，独立环境没有 Playwright，实际 CLI help/status/login-help 正常。真实 stdio 与 Streamable HTTP 均完成 SDK 初始化、列出 38 项工具并调用 `get_capabilities`；名称、输入/输出 schema 和 annotations 与既有快照一致，仅 3 项报修描述更新为 HTTP 语义。HTTP 子进程树与端口在结束后关闭，不启动签到 worker。

独立审查还复现并修复了已登录业务请求的 httpcore DEBUG `Set-Cookie` 泄漏风险。认证与业务共用请求级私密日志上下文，不更改全局日志级别或网络诊断；真实内存传输合成测试覆盖异常恢复、嵌套和其他线程隔离。

默认安装和浏览器兼容测试分别覆盖。首次完整回归的 12 个失败来自旧 UI/浏览器默认假设；已改为显式兼容路径，并新增默认 CLI 指引的真实本地页面检查，不能通过把默认行为改回浏览器来让测试通过。

## 仍需独立验收

真实 HTTP 报修最终提交与学校回执、WebVPN 受保护 OA 及自然到期续登、更多账号、Docker 镜像运行、Linux/macOS、Tailscale/SSH 跨机仍各有验证边界。当前机器没有 Docker。MCP 连接成功不证明宿主具备校园网 DNS 或业务访问路径；部署不应靠关闭 TLS 或安装虚拟桌面掩盖这些差异。
