# 本人理论课表读取与原导出流程衔接

本批按用户要求逐项接入，先补 JW 理论课表取数，复用原课表导出。当前为未发布源码；v0.7.0 发行物和 Hermes 私有 `school_hub` 均未更新。实测发生于 2026-10-24 UTC，用户所在芝加哥仍为 10 月 23 日晚。

## 实现与兼容

- 新增一个工具 `get_academic_timetable(semester="")`，CLI 为 `stu-mcp timetable --semester …`；两者经 App 调用同一 JW 服务。
- 沿用已有 `JwAdapter`、`CampusHTTP`、加密 JW 会话和 `Vault.login_revision`。读取前后在来源锁内核对代次，退出或换号后丢弃旧结果；不新增登录、依赖、数据库、缓存表或后台任务。
- 固定 GET 当前课表表单，再 POST 其当前隐藏字段和节次模式，查询目标学期全部周次及未排课。学期必须来自真实选项；不读取成绩验证课表，也不混用 MySTU 短期日程。
- 课程按来源、学期、课程号及教学班关联。明细可能一课多教师，网格有完整／简略重复展示，不能用表格行数、非空格数作课程数。
- 纯解析处理周次与节次、同课多组安排、未排课、未对应网格的计划教师明细。表头移动／换序保留数据；歧义、未知内容、缺失范围、嵌套业务表和身份冲突明确失败。未匹配教师明细返回 `unplaced_details` 与 `pending`，不假定其没有课。
- `courses[].meetings` 复用原转换器字段。既有 `features/timetable/export.py` 和薄脚本未改，Skill 只更新取数与输入映射。校历、作息、实验课和调课另行核实；查询结果不能自动填导出 `complete=true`。

原 47 个 MCP 工具的契约条目（schema、注解及描述）与改动前逐项一致；只追加第 48 个。`get_schedule` 和 `get_courses` 的参数、语义、缓存不变。课表工具只读，允许联网，按需查询不写入课程／日程缓存。

学校页面没有每组安排的独立不可变主键：同一通知单、星期和节次可以有不同周次的教师／教室安排。当前安排 ID 包含通知单、星期、节次及周次集，教师或教室改变不改变 ID；周次结构改变会产生新 ID。重复导入不承诺更新或去重，不为此新建历史映射库。

## 学校真实读取

最初保存会话过期，使用此前已授权的固定 JW 官方 HTTP 回调，通过现有 `login_http` 完成 HTTPS SSO 认证并加密保存业务会话。密码只发 HTTPS SSO；没有改全局 HTTP 开关、系统代理、DNS 或证书校验，没有启动浏览器。

开发期间的 01:58:25 UTC 当前学期读取成功；随后历史查询遇到失效会话，已停止该次请求，不将缺表单页面解释为“无课”。最终在一次重新认证后集中验证：

| 2026-10-24 02:02:54.176017 | 构建后的 MCP `server.call_tool("get_academic_timetable", {})` | 当前学期 `2026-2027-1`；8 门已排理论课、14 组安排、2 门未排课、1 条计划教师明细未匹配；`status=partial`、`coverage.complete=false` |
| 2026-10-24 02:02:58.156515 | 同一 MCP 入口，真实选项 `2025-2026-3` | 正常历史空学期；0 课程／安排／未排课／未匹配项；`status=ok`、理论页面范围 `complete=true` |
| 2026-10-24 02:03:02.126567 | 独立 CLI 进程 `timetable --semester 2026-2027-1` | 与 MCP 相同的计数和待核对项，退出码 0 |

这三次业务读取均记录 `transport=https`、`cached=false`；认证时用过固定 HTTP 回调与业务本次读取的 HTTPS 分别记录。返回的校历与节次时刻核查标记均为 false，实验课未覆盖。MCP 实测使用当前源码构建的服务器对象，不表示用户各客户端已经更新或私有 School Hub 已部署该工具。

个人课表只在内存处理；回执只保存数量、范围、时点与状态，不保存个人 HTML、姓名、课程安排或凭据。实际校历导出及 WakeUp／Google／Outlook 导入本轮未执行。

## 自动化验收

新增纯解析与服务测试覆盖真实结构对应的合成样本：多教师与多周安排、明细／网格关联、未排课、计划教师缺项、未知内容、空态、表头变化、固定表单、返回筛选、登录失效以及退出／换号代次变化。合成标准化课程直接交给旧转换器，生成 ICS 与 WakeUp CSV；带待核对项时仍由旧核心阻止导出。

入口测试覆盖 CLI／MCP 共用服务、缺登录的原有设置引导、只读注解、能力目录、旧工具契约和原缓存查询。两个 Skill 均通过校验。

首次全量验收发现一处旧教务标签断言，以及设置页原有的两个并发问题：Windows 状态轮询与 WebVPN 标记文件替换冲突（`WinError 5`）；状态响应还可能组合旧账号状态与已完成任务，使页面提前停止刷新。最小修复分别复用现有 WebVPN 短锁、先取任务快照再取账号状态；没有新增重试或更改认证成功判据。新增两个合成回归及原失败 UI 测试通过，修复单独提交。
