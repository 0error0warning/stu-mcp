# v0.6.1 更新功能与发行检查

本记录只覆盖软件更新和发行检查，不把合成响应、安装测试或历史学校登录记录当作当前学校业务成功。
开源 `stu-mcp` 与 Hermes 私有 `school_hub` 分开维护；本次未修改后者，也未升级用户的真实安装。

## 本地检查

Windows / Python 3.12.13：首轮全量 `pytest` 为 **2087 passed, 4 skipped**（269.32 秒）。
随后独立审查补充签名附件日志隐私和损坏安装元数据的错误处理；最终更新专项为 **79 passed**（8.30 秒）。
`ruff check .` 和 `git diff --check` 通过。

更新专项覆盖官方 prerelease 选择、禁止降级、网络失败与未知状态、固定附件地址和 HTTPS 重定向边界、
SHA-256 与 wheel 名称/版本/Python 兼容性、校验失败不执行安装、安装结果与运行版本分离，
以及 CLI/MCP 共用实现、并发互斥、活动报修、设置页和后台保护。
损坏的安装元数据返回未知；安装器开始后失败，旧进程仍要求重启，不能仅凭主包版本未变就继续业务。

## 真实安装器检查

`scripts/check_update_runtime.py` 在临时 uv tools/bin/cache 中离线构造多个合成版本，
实际连续升级 `0.0.1` 至 `0.0.6`，覆盖固定 Python 模块、用户 `stu-mcp` 和 `stu` 命令、
以及内部 Scripts 的两个入口。Windows 五种入口全部通过。

检查 extras、附加依赖、uv 选项、原解释器选择、Python 启动路径、命令入口均保留，
配置与加密会话哨兵文件字节不变；临时下载文件删除后，uv 记录引用的缓存 wheel 仍存在。
Windows 测试发现 `--force` 会重建占用中的环境，当前实现禁止该路径；仅对经安装记录核实的当前
运行 launcher 做有界替换处理，失败不承诺整个环境自动回滚。

这些测试证明安装流程和入口处理，不证明任意 native 依赖均可运行中替换。更新只使用预构建 wheel；
缺少兼容 wheel、依赖冲突或文件占用仍可能失败，需要按返回状态处理。

## 发行包与接口

隔离安装候选 core wheel 后，实际 SDK stdio/HTTP、8 个导出的 MCP 启动配置、3 个技能命令、
课表合成 CSV/ICS 和独立签到后台生命周期检查通过，默认无 Playwright。
新增两个更新工具；原有 45 个工具的名称、输入/输出 schema 与注解逐项保持一致。
47 个工具与提交的契约一致。签到 health 新增可选 `package_version`，协议仍为 1。

候选 wheel 包含 153 项，sdist 包含 298 项；打包源码与工作区一致，未包含运行态密钥、会话或数据库。
最终附件另在标签对应源码上构建，并用发行附件 `SHA256SUMS.txt` 核对下载文件。

真实公网只读检查已读取官方 GitHub 发行列表：当本地候选为 0.6.1、已发布最高为 0.6.0 时，
判定没有可安装的新版本，不执行降级。源码环境识别为源码，不覆盖工作区。
