- 本机 Windows，已安装的 DeepSeek Harness `0.2.1-rc.3`；桌面模型为 DeepSeek-V4.1-Flash（1017，Max）。

- 在新建的“STU MCP 校园功能与通知查询”对话中完成四轮；从桌面轨迹核对工具名、参数和结果，从对话页核对最终表达。

## 实测发现及修复

学生处正文实际位于 `#cont > div.lh200.pl10.pr10`，标题和发布日期为同级节点；此前通用选择器未覆盖此模板。
共用通知解析器现仅在学生处 `News.aspx` 使用该页面结构，并要求唯一的容器、标题、发布日期和非空正文。
不把外围 `#contBg`、侧栏或整个页面当作正文；缺失、歧义、登录与错误页面继续失败。

该站点还以 WebForms 的外层 `form` 包住整篇通知，原附件过滤会把正文附件一起排除。
过滤现只检查正文内部的导航、页眉、页脚和表单，不因正文外部的表单容器丢弃有效附件。
附件支持类型保持已有范围，没有增加 DOC/XLSX 解析或把附件正文读取计入本轮验收。

新增 13 项合成回归覆盖正文范围、附件范围、WebForms 包裹、缺失/重复标题日期正文、导航模板与错误站点路径。
定向检查：`uv run --extra dev pytest tests/test_notice_parsers.py tests/test_notice_service.py -q` 为 **83 passed**；
`uv run --extra dev ruff check .` 通过。
最终全量回归 `uv run --extra dev pytest` 为 **2565 passed、4 skipped**（504.44 秒）；
`git diff --check` 通过，四份接入/验证文档中的 69 个本地链接目标存在。

## 体验观察及未验收范围

- DSH 在第一轮多调用了三次仅取元数据的 `get_notice`；桌面显示该轮用时 1 分 16 秒，回复包含较多验收细节。这是一轮带明确验收约束的观察，不是普通请求的性能基准。
- `get_capabilities` 的 OA 总览仍容易被概括为“需登录”；本次回答同时说明匿名优先通道未验证。能力配置状态不等于匿名网络或业务实测结果。
- 四轮证明桌面能选用并调用这些工具、延续上下文、表达部分失败和缺登录、打开共用设置页，并在重启后使用修复版本。
- 本轮没有验收真人首次登录、登录后个人数据、桌面取消慢请求、即时热重载、长时间运行或其他 agent 的真实应用内交互。
- 此修复落在共用解析器，没有 DSH 专属业务分支。此前桥接组件发现 52 个工具和配置/协议回归的证据仍独立保留，不把四轮对话称为所有工具逐项验收。
