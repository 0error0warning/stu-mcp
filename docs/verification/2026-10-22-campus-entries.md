# 校园入口与功能分类调查：2026-10-22

本轮核对开源 stu-mcp v0.6.2 的来源、认证依赖和 47 个工具，再读取郁金香导航及学校公开目录。结果是入口盘点与接入规划，没有实现新的学校业务、登录或写入。Hermes 私有 School Hub 不在本轮范围。

当前功能和认证的维护说明集中在[校园服务映射](../campus-services.md)。本页只保存此次调查的方法、范围、结果和缺口；[逐项清单 CSV](2026-10-22-campus-entries.csv)是有日期的证据快照，不是运行时注册表或永久可用性清单。

## 范围与时间

日期采用客户端 America/Chicago：2026-10-22。CSV 探测时间采用 UTC；主要入口批次于 `2026-10-23T02:52:26Z` 至 `02:52:42Z` 启动，等于客户端 10 月 22 日 21:52（UTC−05:00）、北京时间 10 月 23 日 10:52。它不是 10 月 18–21 日的历史业务验收。

| --- | --- |

| 导航页面结果 | 首页与 51 个栏目收到 200；校历、地图、VPN说明、电话专题及 v5 共 5 页收到 403，原 HTTP 地址各复查一次仍为 403，未继续重试 |

| 官方补充 | 学校快速通道、网络中心、数学系常用网站、图书馆及少量官方指南/通知，共 317 条参考记录；既含业务入口，也含机构、专题、外部链接和裸 IP |

| 匿名入口探测 | 对 216 个汕大主机的 254 个协议/路径入口做一次有界请求，优先同协议根入口；不会把根入口结果当作每条深层链接已验证 |

导航是第三方线索。用途优先对照[学校快速通道](https://www.stu.edu.cn/kstd.htm)、[网络中心用户服务](https://info.stu.edu.cn/its/wlfw/yhfw.htm)、[图书馆](https://www.lib.stu.edu.cn/)和各系统原页。官方页面本身也会保留旧链接；“官网收录”和“当前业务已验证”分开记录。郁金香导航的购物、娱乐等外部链接没有纳入学校业务候选清单。

本机匿名 HTTP 使用 `trust_env=False`、系统 DNS、正常 TLS 校验，每次最多四跳、10 秒等待、正文最多 96 KiB、并发最多八个。只读公开内容，不携带用户登录态；不跨站继承会话、不输入凭据、不执行 JavaScript，不跟随到外部域或无主机的重定向。应用层忽略环境代理不能证明已绕过系统路由或 TUN；本轮不推断物理校内/校外位置，不改代理、DNS、hosts、网络或证书设置。

目录页的 403 会造成发现范围缺口，外部系统和页面脚本也可能包含本轮未展开的入口。因此这是一轮对**已发布入口**的广泛盘点，不能称为发现了全校所有系统或验证了全部业务。

## 匿名探测结果

| 观察结果 | 入口数 | 解释 |
| --- | ---: | --- |
| 收到最终 HTTP 响应 | 156 | 144 个 200、6 个 400、2 个 403、2 个 404、2 个 502；200 中包括登录页、跳转壳页及 SPA 壳页 |
| 连接异常 `ConnectError` | 70 | 其中 58 次异常明确包含系统解析失败线索；其余保持连接/TLS阶段未知，不改写为证书错误或权威 DNS NXDOMAIN |
| 建连超时 / 读取超时 | 9 / 5 | 只表示本轮路径和预算内未成功 |
| HTTP 协议异常 | 7 | 收到了不符合当前 HTTP 客户端预期的通信，未据此判断停用 |
| 达到跳转上限 | 4 | 包含未登录 Moodle 的 gateway 往返；本轮不保持跨站 Cookie、不执行浏览器脚本，不能据此否定已有认证适配器 |
| 无有效主机的跳转目标 | 2 | `http://repair.stu.edu.cn/` 和 `http://mrp.stu.edu.cn/` 返回 `https:///`；保留原始现象 |
| 外部跳转停止 | 1 | `http://m.stu.edu.cn/` 指向 `https://partner.outlook.cn`，没有跟随认证 |

计数单位是协议/路径入口，不是业务系统；同一主机的 HTTP、HTTPS 和明确补充路径分别计数。失败后不自动改协议再送认证，也不把 200 数量叫作“可用业务数量”。

几个容易误判的具体例子：

- **宿舍报修的旧 HTTP 链接有坏跳转，HTTPS 正常进入 SSO。** 不能因此说报修系统整个不可用。正式适配器仍使用固定 HTTPS 入口。
- **`its` HTTP 连接异常、HTTPS 建连超时。** [网络中心故障报修页](https://info.stu.edu.cn/its/info/1184/4090.htm)仍引用它；没有停用或迁移公告证据。
- **`slc`、`webmail`、`www.scholarship` 等旧链接本轮系统解析失败。** 其中 `scholarship.stu.edu.cn` 的根入口收到“汕头大学奖助学金”页面；这不证明旧申请路径仍可用，也不能凭域名相似自动替换。
- **`sao`、`mms` 根入口返回 404，`qgjx`、`outlay` 根入口返回 403。** 这不能判定该系统所有深层路径都已废弃。
- **本机图书馆 HTTPS 连接未成功，网页检索服务却能读取其官方页面。** 不同访问路径的结果分开保存，不把检索缓存当作本机连通成功。
- **导航“教学项目管理平台”的原链接是 `http://http://project.stu.edu.cn`。** 已记录格式错误，没有擅自修正后把猜测地址标为官方现行入口。
- **[数学系常用网站](https://math.stu.edu.cn/xgwz/cywz.htm)把 `credit` 和 `classroom` 标为“旧”。** 只说明该页面的标注；本轮 `classroom` 仍跳学校 SSO，不代表业务停用，也不代表当前可预约。

## 登录关系的新增证据

本轮没有登录。下面的匿名 302 只证明**入口指向学校统一认证**，不能证明账号权限、业务可读或会话可共享：

| 同指向 `sso.stu.edu.cn` 的入口 | 导航/官方说明的用途 | 产品状态 |
| --- | --- | --- |
| `my`、`repair` | MySTU、桑浦山学生社区报修 | 已有独立 HTTP 业务适配；10/21 的真实验收另见历史记录 |
| `netms` | 流量套餐、校内账号服务 | 仅维护入口与诊断；没有个人流量或改密工具 |
| `dorm`、`power`、`xg` | 宿舍管理、水电、学生事务 | 尚无专用业务适配器；宿舍管理不是宿舍报修 |
| `classroom` | 教室预约旧入口 | 仅匿名跳转证据；预约业务未验 |
| `carfleet`、`hr`、`lrmo`、`sro` | 车队、人事、资源事务、科研 | 仅匿名跳转证据；用户群和业务权限待核实 |

`jw` 根页面还返回指向 SSO 的脚本，但本轮没有执行脚本；它的正式 CAS 认证依据是[10/21 真实 HTTP 验收](2026-10-21-http-default.md)。`r` 的 SSO 依据是[官方指南](https://stuecc.stu.edu.cn/info/1032/1139.htm)和 10/18 登录后表单核验，不能因为本轮首页没有自动跳 SSO 就否认它。`service` 有既有登录查看网络专题的证据，本轮 200 壳页不增加认证结论。

认证还存在这些独立路径，不能归并为“一个学校登录”：

- OA 公告优先原站匿名读取；经 WebVPN 路径读取时使用 `webvpn` 会话，源码 `source=oa`、`session=webvpn` 不表示公告强制登录。员工办公另走 CAS，回调 `office.stu.edu.cn`，尚未适配；详见后续[OA 入口补充核查](2026-10-22-oa-entry-boundaries.md)。补充没有改写本页原批次的时间或 254 项探测统计。
- 雨课堂由本人手机确认官方二维码；对分易沿用原微信回调。二者都是独立平台，不共享学校 SSO 会话。
- [图书馆 FAQ](https://www.lib.stu.edu.cn/faq-page)列出读者账户/一卡通与 MySTU 登录方式；[校外访问说明](https://www.lib.stu.edu.cn/zy/xwfw)另列 CARSI 和 WebVPN。[CNKI 馆方说明](https://www.lib.stu.edu.cn/database/275)给出 `fsso.cnki.net` / `idp-lib.stu.edu.cn` 路由。本轮仅核实文档，没有验证这些认证链。
- 官网邮箱直接指向微软入口；账号可能与校园账号相同，协议及会话仍须独立验证。上网认证、校园卡查询密码、第三方外卖配置也各有边界。

## 接入缺口与建议顺序

这里的优先级是结合本轮证据的产品建议，不是已获得认证/写入权限，也不是已经实现的路线图。

| 顺序 | 具体缺口 | 下一步最小验证 |
| --- | --- | --- |
| 1 | 用户任务找入口；现有 `get_service_links` 无缓存时只常驻四个核心入口 | 以明确的业务 ID 维护稳定入口、别名、任务、校区、认证依赖及证据。先加入已核实的公开目录信息；保留旧工具接口 |
| 2 | 一网通办事项目录与办理指引 | 只读核实公开事项名称、办理部门、材料及“立即申请/跳转办理”目标；门户和后端业务分别建身份 |
| 3 | 图书馆馆藏、数据库目录、公开失物招领与服务说明 | 先验证匿名 HTTP 查询和完整性；不要先要求全部账号或下载订购资源 |
| 4 | 综合报修 `r`：网络故障及其他分类 | 单独验证 HTTP 登录、分类/校区/必填字段契约；只读记录查询先行，写入另做预览、确认及单次提交适配，不复用 `repair` 表单 |
| 5 | 借阅到期、水电、流量余额、个人学工事项 | 分系统验证纯 HTTP 首次认证、本人身份、只读接口和明确空态；共享 CAS 协议层，不共享业务 Cookie jar |
| 6 | 场地/图书馆空间/活动预约与其他课程平台 | 先确定对象、校区及课程实际使用平台，再核实当前入口。预约、续借、挂失、充值、改密、申请等动作各自设计确认和回执 |
| 暂缓 | 人事、科研、财务、档案、裸 IP 系统和历史专题 | 确认学生需求、访问范围及维护状态，再决定是否进入产品；不是所有能找到的站点都需要业务适配器 |

官方材料也表明学校使用[长江雨课堂](https://stuecc.stu.edu.cn/info/1032/1716.htm)、[对分易](https://biz.stu.edu.cn/info/1115/8718.htm)等外部平台。其他课程指定平台需逐课确认，不能凭学校曾使用超星、MOOC 或智慧树就编造当前学校租户入口。

后续配置引导可以按“用户任务 → 一个或多个系统 → 各自认证与网络条件 → 支持的工具”组织。不必增加自动猜测意图的复杂路由；一个简洁、可验证的静态索引即可起步。`get_capabilities` 现有来源状态、认证流程、报修/签到等能力继续保留，新增索引应为增量兼容。

## CSV 字段与复查方式

CSV 使用 UTF-8 BOM，正常链接一行是一个规范化 URL，另保留一条原始格式错误；一行不等于一个系统或功能。机构网站、历史专题、深层资源链接与业务入口均保留原标签和来源，归类依据只是公开名称/说明，未验证用途不冒充业务实测。

配置/功能总表整理时进一步按具体业务路径复核：公开 `opac.php` 馆藏检索不继承个人读者登录要求；MySTU 域内 ELC/CILL 预约不继承课程活动的已接入状态；OPAC 根入口和荐购也分别保留多业务/未核实条件。已修正这四行的目录元数据，未覆盖原探测列、时间或数量。本次没有新增登录或网络探测。

| 字段 | 含义 |
| --- | --- |
| `record_kind` | `published_link` 为发现的链接；`probe_supplement` 仅用于协议或固定路径对照，不冒充来源原链接 |
| `entry_url`、`source_labels`、`evidence_urls` | 原入口、来源标签及旁证页；仅合并根路径表示等差异，保留 HTTP/HTTPS、业务路径和查询差异 |
| `business_group`、`group_basis`、`mcp_scope` | 便于审查的人工分类和当前接入范围；一个主机可能包含多个业务，以具体路径为准 |
| `auth_relation`、`auth_evidence_level`、`auth_evidence` | 登录依赖及证据层级，可能引用历史验证或官方说明，不代表本轮重新认证 |
| `probe_url`、`probe_checked_at_utc` | 实际测试的 URL 和当次时间；空值表示未探测 |
| `exact_url_probed` | `yes` 才代表此 URL 是本轮请求起点；`no` 时最多借用同协议根入口结果，不能证明该链接路径可用 |
| `probe_result`、`probe_http_status`、`probe_failure_hint` | 有界请求结果、最后收到的状态码和可确认的失败线索；中途超时时可能仍有前一跳状态码 |
| `probe_title`、`probe_final_url`、`probe_redirects`、`probe_auth_evidence` | 已读取的匿名标题/最终位置和跳转线索；不保存正文、Cookie、认证票据或真实会话标识 |
| `notes` | 原始格式错误、未探测端口、历史标签、范围限制等 |

复查时先按需求选明确入口和协议，在对应运行主机以匿名直连确认；再独立验证目标业务认证。新的学校接入不能从此次 200、旧缓存、共享 SSO 或历史账号验收推导。产品里的 `diagnose_campus_network` / `audit_campus_network` 仍使用原固定白名单，不把 CSV 当作任意 URL 探测器。

本轮没有读取用户凭据、登录态、个人工单或成绩，没有新增/修改报修、预约、申请，也没有变更系统网络或私有部署。源码审计、匿名网络观察与既有真实业务验收分别保存。
