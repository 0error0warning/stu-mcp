# 2026-11-15 DeepSeek 思考日志与 MCP 使用体验复测

用户明确要求分析 DeepSeek 对工具使用的思考文本后，本轮追加采集 DSH `--json` 输出中的 `thinking` 事件，对照实际工具名、参数、返回值和最终回答。此前[桌面验证](2026-11-15-dsh-local.md)只观察工具轨迹；两阶段的观察范围分别保留。

## 环境与方法

- 宿主为本机 DSH 0.2.2-rc.3，沿用桌面模型路由 `deepseek-official / deepseek-flash`、Max。独立 headless profile 复用 DSH 托管认证，没有读取或复制模型密钥。
- 基线是独立安装的官方 STU MCP 0.7.7。候选从同一 wheel 提取，只替换共同核心的 `server.py` 和 `features/notices/presentation.py`；没有混入工作区的教务/MySTU 协议草稿，没有为 DSH 另写业务适配器。
- 两侧均声明同样的53个工具，使用各自隔离的运行目录、空学校会话及相同的170条公开列表初始记录。停用个人技能、全局项目指令和额外文件/命令/网页工具，研究 MCP 本身的提示效果。公开读取正常执行，非任务范围操作受限；实际对照未触发范围拒绝。
- 初轮使用固定正文和验证码响应，随后改为真实公开 HTTP：初始缓存仅保留列表元数据，正文与附件经正式适配器联网读取。原生 MCP 预检确认真实页面正文17字，真实附件返回学校验证码。
- 原始工具事件与汇总位于 Git 忽略的 `output/dsh-followup-20261115/`。DeepSeek 思考文本单独私密保存于应用数据目录，不进入 Git；公开记录只写行为摘要。JSON 日志会截断过长事件，不能声称保存了全部思考。

对照两侧使用同一道题：

> 请用 STU MCP 整理《汕头大学大学生创新创业竞赛激励办法》的奖励标准和申报条件，并给出原文依据。只查公开信息，不使用个人账号，不修改文件。

## 用户反馈后的修订

用户要求进一步写明验证码后的停止条件，不要求修正建议贴回正文的行为，并将50条上限提高为100。因此当前源码调整为：

- `handoff_required=true` 表示当前附件的全文自动获取已经结束。立即交付原文链接；不得为补齐该附件继续调用下载、OA刷新、缓存遍历或其他工具。明确说明“用户要求总结条款”不等于“用户明确要求找替代版本”，未答出条款不能成为继续调用的理由。已经明确授权的替代版本检索仍可继续。
- 撤回对建议上传、粘贴正文或下载后返回的新增限制。用户提供内容后可以继续分析，仍不索要验证码或要求用户完成验证后回来续调。
- 缓存查询与来源刷新的实际校验、错误提示和 MCP Schema 上限都改为100，默认20条不变。查询偏移、正文字符数、来源页数和请求预算保持原样；100条是允许的数量上限，不是所有来源实际返回数量的承诺。

修订候选重新从官方0.7.7 wheel提取：覆盖 `server.py`、`store.py`、通知 `presentation.py`，`app.py` 只修改刷新数量限制，未带入工作区的教务过滤草稿；此前候选目录保留。

| 修订后场景 | 实际 MCP 调用 | 结果 |
| --- | ---: | --- |
| 与上节相同的办法条款问题，真实公开 HTTP | 4 | 收到验证码后无后续工具调用；思考文本明确识别停止条件。最终仍建议用户提供正文或明确授权替代检索，按用户意见保留 |
| 只从缓存取100条，报告数量与下一页位置 | 1 | 直接使用 `search_notices(source="public", limit=100, offset=0)`，成功返回100条及 `next_offset=100`，未刷新或先触发参数错误 |
