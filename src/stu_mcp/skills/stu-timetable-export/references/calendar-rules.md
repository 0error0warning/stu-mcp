# 规则归并与课次核对

## 基础范围

校历、个人课表和节次时刻表分别核对。课表中的“第1周”要对照学校实际周次含义，明确其星期一日期；报到日、实践教学起点和课堂教学起点不能自动互换。按用户适用校区/对象使用时刻表，统一 `Asia/Shanghai`，不依赖 agent 主机时区。

保留课程/教学班及每组授课安排的稳定身份。同名课程不自动合并。离散周次、单双周、多教师/教室及多段上课时间分别表达；缺值不猜默认星期、节次或日期。考试安排不混进授课课表，除非用户明确需要且有相应来源。

## 停课、改期和按日调课

把通知解释为有证据的显式规则：

- 取消：指定日期和课程/范围不发生授课。
- 改期：将原教学日期的指定课次移至目标日期，原课次取消；保留原身份以便比对。
- 按另一日期课表上课：说明目标日期采用哪一原教学日期的课程，以及来源日期原课是保留还是取消。通知没说明时不推定；需要查看相关条款或询问。

周末“补周一”必须确定采用哪一教学周/实际教学日期，不只改星期数字。目标日原课如何处理也需明确；“补课”二字不足以自动删除另一门正常课程。节假日期间学校是否停课、教学周编号是否继续推进，均按学校依据，不用全国工作日算法猜。

同一规则记录适用对象、原日期、实际日期、来源和核查时间。多次调整同一课次、调整目标已有课、来源日期无匹配课次或通知冲突时列出受影响部分。脚本只实施已经解释清楚的输入，不负责从自然语言决定谁优先。

按适用范围和明确修订/替代关系处理冲突：专项通知不能无条件改全校，一般通知也不能抹除仍有效的专项安排。时间较新是核对线索，不是自动全局覆盖规则。无法消歧的规则进入 `pending`，不隐藏或输出看似完整的文件。

## OA 开关与报告

默认 `oa.enabled=false, status=not_checked`，不进行任何主动 OA 查询。用户明确开启才检索与目标学期及跨年日期范围相关的放假/停补课、更正通知，并记录关键词、时间范围、缓存/分页限制和检查时间。开启但读取失败/覆盖不足时保留待核实项，不记为 checked。查询结果本身不能改变用户设置。

关闭时以已经核对的校历、课表、公开规则和用户提供资料生成，交付说明“未检索 OA 专项调课通知”；这不自动让整个任务失败，也不等于“已确认没有额外调整”。用户随后开启，应补查、展示课次差异、生成新目录文件，不覆盖或删除已导入的远端日历。

## 验收

对照首/末教学周、单双周切换、校历假期、每个取消/改期/按日调整、离散节次和教室。核对按课程的基线课次数、取消/新增数量与最终实际日期，检查重复身份和时间冲突。

导出报告保留校历版本/读取时间、完整课表来源、采用规则、OA范围和每目标状态。生成时间不能替代证据核查时间。格式检查通过只证明文件可解析；目标App实际导入正确与学校安排正确仍需分别核对。
